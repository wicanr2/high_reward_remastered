# 007 原版音樂與音效播放

狀態：DRAFT（2026-10-03，第一版，未經審查）
範圍：讓 `apps/hr/play` 前端播出原版的背景音樂（`.MID`）與音效（`SOUND_E.PCM`）。做法是在 `apps/hr/runtime` 掛聲音常式的進入點，把事件交給一個與 ebiten 無關的合成與混音套件，前端再把它接到音訊裝置。不含：模擬 `CTMIDI.DRV`、Sound Blaster DSP 與 8237 DMA、`OP.EXE` 與 `END.EXE` 的聲音、無頭執行（機器人、診斷、測試）的聲音輸出、貼近原版音色的保證。
關聯：`docs/re/018-music-content-and-hooks.md`（證據，本規格的位址與格式都引用它）、`docs/re/010-music-subsystem-DRAFT.md`（遊戲端聲音子系統）、`docs/spec/003-runtime-and-frontend`（保留鍵、前端）、`docs/spec/006-frontend-help-theme-language`（F1 說明要列出本規格的按鍵）。

推論等級用法：confirmed、強推論、假說、未知。沒有標的敘述是設計決定。

## 1. 輸入與工具

| 項目 | 內容 |
|---|---|
| 原版 | `MAIN.EXE` SHA-256 `08ed144e8f8d6e97d19f0759bce2420665998143f2f0f056ab7adc718e550e3e`（`Session.Open` 已驗證）；27 個非空 `.MID` 與 `SOUND_E.PCM` 的大小與雜湊在 `apps/hr/runtime/required.tsv` |
| 位址系統 | 執行期 `段:偏移`；聲音常駐段 `192B`（IDA `281B` 減 `0EF0`），資料段 `3E24`（IDA `4D14`）；`2BCC` 段的曲號（`docs/re/010` 第 2.3 節） |
| 工具 | dosgolem 分支 `hr`；`tools/music/run.sh midiinfo`（MID 與 PCM 的結構統計，`docs/re/018` 第 0 節）；Go 容器 `tools/play.sh`、`tools/dosgolem.sh` |
| 新程式 | `apps/hr/sound`（SMF 解析、FM 合成、混音，純 Go，不依賴 ebiten）；`apps/hr/runtime/sound.go`（進入點掛鉤）；`apps/hr/cmd/hrmusic`（離線轉 WAV，驗證用）；`apps/hr/play` 的音訊接線 |

## 2. 設計總覽

```text
遊戲 ──呼叫──> 192B:0010/0061/00A0/011F/0274   旗標 3E24:01B8 維持 0，函式本體照原樣空轉返回
                     │ 進入當下由 runtime 觀察
                     ▼
              runtime.SoundSink（介面）   MusicStart(mid) MusicStop() MusicFade(n) SFX(slice) Playing() bool
                     │
                     ▼
              sound.Engine（合成、混音，執行緒安全）  <──拉取── 前端音訊裝置（ebiten audio）
```

- 遊戲環境不注入 `SOUND`、不載入驅動，旗標維持 0。這與 `docs/re/010` 的選項 A 與 D 一致，沒有模擬硬體，也不需要 `CTMIDI.DRV`。
- 掛鉤只在進入點觀察與寫一個狀態字，不取代函式本體，不改變遊戲的控制流程。

## 3. 進入點與動作

位址、位元組與參數位置見 `docs/re/018` 第 4 節。`Session.Open` 在 `Options.Sound` 非空時，逐一比對下列進入點開頭 16 bytes，任何一處不符就回傳錯誤（失敗即關閉，不猜測套用）。

| 進入點 | 觸發當下（執行前） | 動作 |
|---|---|---|
| `192B:0010` 開始 | 一次呼叫 | 從 `[3E24:01CE]:[3E24:01CC]` 起讀出 MID，長度上限 `0x4E20`（遊戲 `fread` 的上限，`docs/re/010` 第 2.1 節），呼叫 `Sink.MusicStart(mid)` |
| `192B:0061` 停止 | 一次呼叫 | `Sink.MusicStop()`，立即停（不淡出） |
| `192B:00A0` 淡出 | 一次呼叫 | 讀 `SS:SP+4` 的低位元組為係數 `n`，呼叫 `Sink.MusicFade(n)` |
| `192B:011F` 音效 | 一次呼叫 | 讀 `SS:SP+4` 為 `id`；`0x32 ≤ id ≤ 0x3B` 呼叫 `Sink.SFX(id)`，其餘忽略並記一次日誌 |
| `192B:0274` 查詢 | 一次呼叫 | 先把 `3E24:01BA` 的 bit 0 寫成 `Sink.Playing()` 的值（其餘位元不動），再讓原函式執行（它回傳 `01BA & 1`） |

行為語意：

1. `Sink.Playing()` 為真的條件：已開始且尚未自然結束，也不在被 `MusicStop`、`MusicFade` 終止的狀態。`MusicFade` 呼叫後 `Playing()` 立即為假，使 `PlayMusic` 的 `0274` 迴圈不阻塞（`docs/re/018` 第 4 節第 3 點）；淡出本身由引擎在音訊端完成。
2. 引擎收到 `MusicStart` 時若淡出尚未結束，新曲排到淡出結束才開始（最多一首排隊，後到者取代）。排隊中的曲子視為「播放中」。
3. 自然結束時 `Playing()` 變假，之後的 `0274` 把 bit 0 清掉，遊戲的重播節拍（`1043:223C`）延遲一個節拍後重播目前曲號，循環由遊戲自己的狀態機完成，前端不另做循環。
4. 淡出長度：`13 × 2 × n ÷ 18.2065` 秒，`n ＝ 1` 時約 1.43 秒（強推論，來自 `docs/re/010` 第 3.2 節的原版淡出，計時器週期未驗證）。
5. 音效：單一聲部，新的 `SFX` 取代尚未播完的舊音效（原版只有一組 DMA，`docs/re/018` 第 3 節第 9 點）。切片取 `[table[id−0x32], table[id−0x31])`，`table` 讀自執行期 `3E24:0008` 的 11 個 word，不寫死在前端；取樣 8 位元無號、8000 Hz。原版多播 1 個樣本，前端不重現（第 9 節已知差異）。
6. `MusicStart` 收到解析失敗的資料（沒有 `MThd`、軌數為 0、長度超過上限、事件截斷）時，忽略並記一次日誌，`Playing()` 維持原值。`ALCOHOL.MID` 是 0 byte，遊戲讀 0 byte 後緩衝保留上一首，所以那次 `MusicStart` 收到的是上一首（與原版行為一致，強推論）。
7. `Options.Sound` 為空時，掛鉤整個不存在（每步多一次與 `nil` 的比較），遊戲行為與現況完全相同，包含 `docs/re/010` 第 4.2 節的重複讀檔。非空時，遊戲可見的差異只有 `3E24:01BA` bit 0 與其後果（不再重複讀 MID、`2BCC:0224` 與計時器 `0Dh` 依遊戲的節拍邏輯動作）。

## 4. 合成與混音（`apps/hr/sound`）

| 項目 | 規格 |
|---|---|
| 輸出 | 立體聲 16 位元小端，44100 Hz。單聲部內容以相同音量送兩聲道（原曲沒有聲像資料，`docs/re/018` 第 1 節第 3 點） |
| SMF | 格式 0 或 1，division 為每四分音符 ticks；合併所有軌並依絕對 tick 排序，相同 tick 時 note-off 先於 note-on；速度事件依序生效；支援 running status、`meta51`、`meta2F`；其餘 meta 與 sysex 略過。不支援 SMPTE division（遇到時解析失敗） |
| 事件 | 音符開關、program change、控制器 7（音量）；其他事件略過（原曲只有這些，`docs/re/018` 第 1 節第 3 點）。通道 10 當打擊樂 |
| 合成 | 雙運算元 FM（調變器與載波各一個正弦與 ADSR、調變器回授），本專案自行設計的參數表，不使用也不複製任何現成音色庫。`docs/re/018` 的 22 個 program 各有一組參數，其餘 program 依 GM 的 8 個家族（每 8 號一族）取預設。打擊樂：大鼓（36）、小鼓（38）、低音筒鼓（45）、開放式 hi-hat（46）、碎音鈸（49）各一組合成，其他音符號用相近者 |
| 複音 | 上限 24 聲部；超過時取代最早的已進入釋放階段者，其次最早的聲部 |
| 音量 | 控制器 7 與力度相乘；主音量固定為使 27 個檔的離線轉檔峰值落在 0.2 到 0.9 之間（第 8 節驗收） |
| 音效混入 | 8 位元無號、8000 Hz，線性內插升到 44100 Hz，與音樂相加，限幅 |
| 確定性 | 相同 MID、相同取樣數得到逐位元相同的輸出（不使用隨機數或牆上時鐘；打擊樂的雜訊用固定種子的線性同餘產生器） |
| 執行緒 | `Engine` 的 `MusicStart`、`MusicStop`、`MusicFade`、`SFX`、`Playing` 由模擬執行緒呼叫，`Read` 由音訊執行緒呼叫，內部以互斥鎖隔開；`Read` 不配置記憶體 |

## 5. 前端（`apps/hr/play`）

- 開啟時以 ebiten audio 建立 44100 Hz 的 context，把 `Engine` 當 `io.Reader` 餵給播放器。建立失敗（沒有音訊裝置、容器內執行）時印一行日誌，之後靜音運行，不影響遊戲。
- F3 切換聲音開關（同時控制音樂與音效），預設開。關閉時 `Engine` 仍接收事件並推進，只是輸出填 0，這樣再開啟時節拍與遊戲狀態一致。F3 要補進 `docs/spec/003` 第 7 節的保留鍵表與 `docs/spec/006` 的 F1 說明。
- 命令列 `-mute` 與環境變數 `HR_MUTE=1` 起始就靜音。
- 前端把 `SOUND_E.PCM` 的位元組在開啟時讀進記憶體交給 `Engine`；檔案缺失或大小不符 `required.tsv` 時，音效關閉，音樂不受影響。

## 6. 失敗模式

| 情境 | 行為 |
|---|---|
| 進入點位元組不符（版本不同） | `Session.Open` 回傳錯誤，列出不符的位址與實際位元組 |
| 沒有音訊裝置 | 靜音，日誌一行；`Engine` 仍運作，遊戲行為不變 |
| MID 解析失敗 | 忽略該次 `MusicStart`，日誌；不影響遊戲 |
| `MusicStart` 太頻繁（每 tick 一次） | 因為 `Playing()` 為真時遊戲不會重載，正常情況不發生；若發生（引擎回報結束又開始），日誌限速（沿用 `ratelimit`） |
| 引擎累積延遲過大 | 前端播放器緩衝固定為 0.1 秒；不追趕，不丟事件 |
| `SOUND_E.PCM` 缺失 | 音效關閉 |

## 7. 玩家垂直路徑與存檔影響

啟動遊戲後 `PlayMusic(16)`（`SCOUT.MID`）一次（`docs/re/010` 第 2.2 節），標題畫面應有音樂；選單點擊有音效（`PlaySFX(0x32)`，`docs/re/010` 第 2.2 節）；進入遊戲後換曲、戰鬥曲、結束曲由遊戲自己決定。存檔格式與內容不變：聲音狀態都在 `3E24` 與 `2BCC` 的資料中，前端不寫入存檔；讀檔後遊戲的目前曲號由遊戲載入，下一次 `PlayMusic` 或重播節拍觸發時才換曲。

## 9. 原版 oracle 與已知差異

沒有原版聲音錄音，也沒有 `CTMIDI.DRV`，所以不做「與原版聲音對拍」，只對拍遊戲端協議（進入點、參數、狀態字）。已知差異：

| 差異 | 說明 |
|---|---|
| 音色 | 合成器是本專案設計的 FM 參數，不是原版 `CTMIDI.DRV` 的音色；對原版的貼近程度：未知 |
| 淡出與換曲 | 原版換曲要等淡出完才讀新曲，期間遊戲忙等；本實作不阻塞遊戲，新曲排在淡出之後，聽感相同，遊戲內時序略有不同（少約 1.4 秒的忙等） |
| 音效長度 | 原版多播 1 個樣本與開頭 4 bytes 的檔頭當樣本；本實作取表值的半開區間，切片 0 同樣含檔頭（與原版一致），不補多出的 1 個樣本 |
| 混音 | 原版音效與音樂各走各的硬體（DMA 加 FM），本實作軟體相加並限幅 |
| 重複讀檔 | 有 Sink 時消除（`docs/re/010` 第 4.2 節的 86 次降為 1 次），無 Sink 時不變 |

## 10. 停止線與權利邊界

- 引擎與參數表是本專案自己的程式與數值，不含任何原版位元組。原版的 MID 與 PCM 只在執行期從玩家自備的原版目錄讀入。
- 離線轉出的 WAV 是原版音樂的衍生物，只放 `workplace/out/music/`，不提交、不進發行包。發行包不含音訊檔，只含引擎。
- 本規格不涵蓋：模擬 `CTMIDI.DRV` 的硬體路徑、播放原版沒用到的曲目、音量與音色的使用者設定畫面、`OP.EXE`／`END.EXE` 片頭片尾的音樂。要做這些先改規格。
- 只有被前述測試（尤其是 runtime 掛鉤測試與前端冷啟動）覆蓋的路徑才能稱為「已支援」。在使用者試聽並接受之前，不寫「原版音樂已完整重現」。
