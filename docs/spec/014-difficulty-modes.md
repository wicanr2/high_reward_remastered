狀態：CONFORMED。日期：2026-11-03。

| 範圍 | 需求 |

| 遊戲進度 | 兩種模式使用不同進度，不混用存檔。 |

## 實作契約草案

固定輸入及位址空間沿用 037。MAIN.EXE 全檔 SHA-256 必須相符，高難度另完整驗證 RequiredFiles。程式只修改執行記憶體及高難度資料副本，原始來源唯讀。

### 啟動與進度

- 前端預設先顯示兩張選擇卡，再建立 Session。滑鼠點卡片或方向鍵／Tab 選擇，Enter 開始，Esc 離開。原版預設取得焦點。選單採現行深色面板與 Noto 字型，五語文字沿用前端語言。
- 選單取消不建立 profile、不執行 CPU。選定高難度後若啟動失敗，保留模式並顯示錯誤，不切回原版。語言包失敗可沿用既有原語言回退，但難度不變。
- `-difficulty original|hard` 可直接啟動指定模式；未知值回錯。未指定時每次顯示選擇頁，不把上次難度寫成自動略過選擇的偏好。
- `Options.Difficulty` 零值為原版，原版仍使用原本 SaveDir。高難度的 SaveDir 由同一基底加上 `-hard`，預設為 `high_reward/saves-hard`；自訂 `-saves` 同樣套用。呼叫端不能用同一目錄同時開兩種模式。
- 高難度必須有可寫存檔基底，不能以唯讀模式悄悄共用原版。目錄放 `difficulty.json` 標記 `hard-v1`。原版拒用含此標記的目錄；高難度拒絕採用沒有標記且已有內容的目錄。
- 新索引固定五行，每行四個非空 token，槽位為 0 至 4，日期用 `----/--/--`，時間用 `--/--/--`，地名用 ASCII `EMPTY`。載入時按原始 byte 長度檢查日期最多 10、時間最多 9、地名最多 21，槽位須為對應單一數字。時間加 NUL 必須小於或等於相鄰日期欄位間距 10 bytes，不使用 10-byte 日期字串填時間。沒有 GAMEFILE 檔案的槽位由原版載入函式正常回傳失敗，不冒充已存檔。
- 標記或 FNAME 遺失、索引錯誤、符號連結造成來源與存檔別名，均回錯並保留資料。不自動搬移或刪除玩家存檔。
- 已存在的 GAMEFILE 五槽逐檔檢查為 31,839 bytes；截斷或其他長度的存檔保留原檔並拒絕載入。缺檔代表尚未存入，不產生替代內容。
- 高難度建立 `saves-hard/data-v1/`，只投影 RequiredFiles，不帶原版 GAMEFILE。每個輸入先驗原始雜湊，投影逐檔驗證；FNAME 的 DOS 讀取由獨立暫存層覆蓋。投影有未知檔案時回錯，不能從根目錄回退到原版進度。
- 語言包仍由未修改的來源建置及驗證。現行 Verify 只驗 manifest 自列項目，不能獨自阻擋進度檔；高難度綁定後新增語意允許清單，只容許 COUNTRY.MES、SP.MES、SYSTEM.MES、UWASA.MES、POWERMES.MES、ESPMES.MRG、SHOPTAB.TBL、CFONT.15。其他檔案包含 GAMEFILE 或 FNAME 均回錯，不能成為進度的第二來源。測試須包含 manifest 自列進度檔仍遭拒絕。

### 高難度規則

| 規則 | 接線與邊界 |
|---|---|
| 初始債務 | 第一次 CPU 指令前驗證執行期 `0x37A34` 為 10,000,000，改為 50,000,000。原版存檔讀回包含此值，不在讀檔後再乘。現金 8000、定期償還額度 5000 維持原值。 |
| 劇情給錢 | 只匹配下表 13 組獎金通知及加錢 caller。共享 helper 執行前將 32-bit 正金額除 2，向下取整。通知與入帳各修改自己的引數一次。退款、賭金、金庫提領、一般工作報酬及交易不套用。 |
| 劇情敵軍 | 只匹配下表 9 個劇情挑戰 caller。`7718:015C` 在敵方建立完畢後，將敵方 35-byte 記錄的 `+9/+11/+15/+17` 四個 16-bit 欄位乘 3 再除 2，向下取整。現生命、最大生命、基本攻擊、基本防禦各改一次，玩家表、兵種、數量、裝備與經驗欄位不動。 |
| 北方飛機商店 | 北方 region 7 的 town 57／slot 4、town 60／slot 6、town 63／slot 6，共三格。對應 SHOPTAB.TBL 檔案位移 `0x2D04/0x2F8E/0x31E6` 的類型 `38/3B/3A`。常駐 loader 執行期 `1C19:0063` 讀入後，在 `3A40:050C` 的 200-byte buffer 將該格 `+24` 改為 `FF`。此時 BP+6 為城鎮，指令特徵 `83 C4 14 BA 40 3A B8 0C 05`。語言層或暫存層載入的表也經相同掛鉤，不能蓋回商店。原版選單跳過此類型，城市與通行不刪除，其餘 17 間航空商店不變。 |

劇情戰鬥的 `sub_245EA` return IP：`6EE9:034D/0A59/10BA/26C1/27EF/3BB8/3E35/4DC1`、`749C:20C6`。排除 `669D:0029` 催繳遭遇。戰鬥主函式的上一層必須為常駐 `1514:0602`，BP+12 的 mode 為 7、BP+6 的玩家隊伍小於 6；再沿原版 BP 鏈核對上述劇情 caller。敵方 DS 為 `4D04`，表 `0591`，有效筆數 `0008`，最多 11 筆，配置指標 `0E99` 必須有效。

高難度掛鉤檢查 MAIN 雜湊、指令特徵、SS／BP 範圍、overlay 對應及金額／能力範圍。身份或範圍不符時停機回報，不能默默漏套倍率。能力放大後必須介於 0 與 32767；原值為 0 時維持 0。掛鉤在同一戰鬥建立時只執行一次，下一場可重新套用。

`Machine.Step` 可能先派送 IRQ，再執行 ISR 指令。獎金、商店與敵軍的變更須保留本次 CS／IP／SS／SP／BP 標記，直到 `Machine.Insn` 與該指令實際造成的 SP 變化證實它已執行。IRET 返回同一掛點時不重複修改；下一次呼叫即使重用相同堆疊位置仍須正常處理。正對照將 IRQ0 精確排於通知、入帳及商店掛點前，每項連續驗兩次。

原版寫死於敘事對白的金額文字可能仍保留原數字，實際獎金通知及現金依倍率。選單明示劇情獎金減半。提高生命自然影響原版依最大生命計算的戰鬥獎勵，本次不另改其公式。

### 驗證與停止線

- 原版：同狀態、同輸入的畫面及遊戲記憶體與基準相同。
- 規則：13 組通知／入帳逐項驗證，退款及賭金反例；9 個劇情 caller 與催繳反例；四欄位精確差異、重複呼叫及溢位拒絕；全城鎮載入後 buffer 差異必須只有三個 type byte，來源及投影 SHOPTAB 雜湊不變。另驗語言層載入及重複載入。
- 存檔：兩模式新遊戲、正常存檔／讀檔與重開交錯；原始資料不變，hard 不得載入來源的 GAMEFILE；標記遺失或污染回錯。
- 前端：實際視窗選擇兩個模式、滑鼠及鍵盤、五語字模與文字邊界。正常玩家路徑至少驗一項劇情給錢及戰鬥，不以 direct-entry 取代。
- 原版 oracle 用 dosgolem 固定時鐘與種子；局部引數測試明標為接線診斷，不能宣稱完成完整劇情。未覆蓋的劇情完整通關與 Windows／macOS 原生操作保留限制。

## 驗證方向

- 原版模式：同狀態、同輸入下的金錢、部隊與地圖結果維持既有行為。
- 高難度模式：逐項驗債務、劇情獎金、敵軍及指定商店，再走正常啟動與存讀檔。
- 進度隔離：交錯儲存、重開及載入兩個模式，核對 FNAME／五槽與根目錄回退。
- 修改資料時：原版先驗證，高難度差異綁定版本及原始雜湊；不改成接受任意未知資料。

本項未授權發布新版 Release 或公開散布原版資料。驗證結論限本規格實際覆蓋的功能。

工具列立即切換由 [015](015-toolbar-difficulty-switch.md) 延伸，保留本規格的難度規則與進度隔離。它另行管理遊戲暫停、取消、失敗復原與重啟，不在現有存檔內換算難度。
