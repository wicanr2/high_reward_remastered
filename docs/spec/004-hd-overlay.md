## 1. 範圍與不變條件

範圍：`MAIN.EXE` 遊戲畫面中，經 `2B47:0022` 精靈貼圖、串流解碼進 VRAM、24x24 遮罩精靈快取三條路徑繪出的圖像。
排除：線條、字形、板面圖樣（`docs/re/009` 第 3 節）；它們只出現在基底層，HD 精靈蓋在它們上面時仍是低解析度。`OP.EXE`、`END.EXE`。

- HD 只影響呈現。遊戲邏輯、座標、尺寸、記憶體與 VRAM 內容不變；遊戲看到的永遠是原版的 `640x480` 索引色畫面（遊戲區 `640x400`，第 40 至 439 列）。
- 沒有 HD 素材（缺檔、雜湊不在清單、驗證失敗）的位置，顯示原版像素的放大，不報錯。
- 原版檔案不複製進 `hd/`；`hd/` 只放美術處理後的 PNG 與記錄。PNG 是原版素材的衍生物，repo 維持 private。
- 輸出倍率 `S` 固定為整數；素材以 `S ＝ 2` 製作（`1280x800` 遊戲區）。其他倍率的素材放不同目錄，不混用。

## 2. 為什麼用「驗證式疊層」

遊戲直接寫 VRAM（planar）。精靈被後來的視窗蓋住、被保存背景還原、與其他精靈重疊時，VRAM 會回到別的內容。HD 層若只記「這裡有一張圖」就永遠畫它，被蓋住的部分會露出來。所以每個戳記在每一幀都和 VRAM 當下的內容比對，只在 VRAM 像素等於該精靈原版像素的位置畫 HD 像素：被蓋住的部分自動不畫。

單靠比對不夠：游標移走後，舊位置仍有約 15%（42 個、共 272 個）不透明像素與背景同色，戳記會殘留。所以另有明確的失效規則（第 4 節）。

## 3. 識別：以解碼後的像素內容為鍵

雜湊定義只有一種：`SHA-256(w ∥ h ∥ 索引色位元組)` 的前 16 個十六進位字元。`w`、`h` 是 u16 小端，索引色位元組是逐列、每像素一個位元組，值 0 至 15 是顏色，16 表示透明（遮罩為 1 的像素）。

- 離線：`tools/hd/catalog.py` 對 `tools/img` 解出的 PNG（索引色，16 為透明）計算，寫入 `hd/catalog.tsv`。與儲存格式無關（壓縮與否、平面或 packed 都一樣）。
- 執行期：精靈貼圖由記憶體內的 5 bytes 標頭加平面資料解出索引色（`docs/re/006` 第 4 節），無需知道它來自哪個檔案或是否曾被解壓。串流解碼進 VRAM 的圖像，在函式返回時由 VRAM 矩形讀出索引色（矩形取自呼叫參數與串流標頭）。
- 兩邊用同一個函式（`apps/hr/hd` 的 `Hash(w, h, idx)`）；`tools/hd/catalog.py` 對它做跨語言測試向量。

這避開了三個已知問題：記憶體內精靈的來源指標有 5 種來源（`docs/re/009` 第 6.1 節），不能反查檔案；`348F:0005`（`259F:0005`）收到的是已解壓資料，不是壓縮串流（審查實測 `4040:0000` 為 `80 00 A0 00 80`）；`2E92:0414`、`066A` 的壓縮長度不在標頭。

按參數識別的例外：`PXZ` 戰場地圖（`234A:000A`，只寫 span）與 `GMAP.PXS`（`20C2:25A1`）不在 VRAM 矩形上整張寫入，無法用矩形雜湊。這兩類在 `hd/hooks.tsv` 以「呼叫參數」識別：`297D:0039` 的地圖號對應 `MAPnn.PXZ`（`docs/re/009` 第 6.4 節）、`297D:0002` 對應 `GMAP.PXS`。

### 3.1 `hd/catalog.tsv`

| 欄位 | 內容 |
|---|---|
| `hash` | 第 3 節的雜湊 |
| `id` | `檔名:項目號`，例如 `SPOINT.MRG:14`；相同內容的精靈合併成一列，`id` 以分號列出全部 |
| `w`、`h` | 原版像素尺寸 |
| `kind` | `sprite`、`mask`、`bg`、`face`、`map` |
| `hd` | 對應的 HD PNG 相對路徑（空 ＝ 尚無） |

游標（40x32，工作副本 `DS:1BD1`）不在清冊內：它由 `28EB` 段在執行期從 `CURSOR.MRG`（24x24）轉換產生（`docs/re/009` 第 6.4 節）。執行期的記錄模式（`-hd-record`）把未識別的雜湊與矩形、出現次數寫成 `hd/unknown.tsv`，游標的 HD 素材在那之後以雜湊加入清冊。

## 4. 戳記

### 4.1 鉤子（`apps/hr/hd`）

在 `CS:IP` 走到登錄位址時呼叫回呼。回呼只讀記憶體與暫存器，不寫入，不改變遊戲執行。進入點的堆疊（far call，尚未 `push bp`）：`[SS:SP]` 返回 IP、`+2` 返回 CS，參數從 `+4` 起。

| 進入點（執行期） | IDA | 參數 | 戳記 |
|---|---|---|---|
| `1C57:0022` | `2B47:0022` | `+4` 旗標、`+6` x、`+8` y（遊戲座標，VRAM 列要加 40）、`+0Ah` 精靈偏移、`+0Ch` 精靈段 | 旗標為 0：解出索引色（含遮罩），雜湊，產生戳記。旗標非 0 不畫，不產生戳記 |
| `2378:112A` | `3268:112A` | 槽號、來源遠指標 | 記下槽號的內容（來源 `+5` 起的 360 bytes，24x24 無標頭）與雜湊 |
| `2378:1155` | `3268:1155` | 槽號、x、y | 以槽號的內容產生戳記（24x24 遮罩精靈） |
| `259F:0005` | `348F:0005` | 解壓資料遠指標、VRAM 偏移 | 返回時（見下）由 VRAM 矩形讀索引色；矩形左上由偏移換算，尺寸取自資料的前 4 bytes |
| `1FA2:0414`、`1FA2:066A` | `2E92:0414`、`066A` | 壓縮串流遠指標、VRAM 偏移 | 返回時由 VRAM 矩形讀索引色；尺寸取自串流解壓後的標頭（`docs/re/009` 第 4.2 節） |
| `208D:0039`、`208D:0002` | `297D:0039`、`297D:0002` | 地圖號（`0039`）；無參數（`0002`） | 按參數識別（第 3 節）：`MAPnn.PXZ`、`GMAP.PXS` |
| `1F69:0169`、`1F69:00B5` | `2E59:0169`、`00B5` | 保存區遠指標；x÷8、y、保存區遠指標 | 失效規則 2（見下），不產生戳記 |

返回鉤子：進入時記下返回位址與 `SP`；`CS:IP` 回到返回位址且 `SP` 等於進入時的 `SP ＋ 4`（far return 彈出兩個字組）才觸發。各串流函式是正常 `retf`（審查查過，沒有不返回的路徑）；SP 對不上的情形（函式被打斷）就丟棄這一筆。

### 4.2 戳記佇列與失效

戳記欄位：種類、x、y、w、h、雜湊、期望像素（索引色，16 為透明）、建立時的 DAC 快照、序號。

- 以 `(x, y, w, h, 雜湊)` 為鍵去重，同鍵的新戳記取代舊的並取新序號。
- 失效規則：
  1. 取代：同一位置的新戳記取代舊戳記（鍵相同）。
  2. 還原：保存區還原呼叫（`2E59:0169`、`00B5`）寫回的矩形，完全包含某戳記矩形的，立即移除該戳記（游標的移動由此清除舊位置，不依賴比對）。保存區標頭的 x、y、寬、高在 `docs/re/009` 第 8.1 節。
  3. 比對失敗：一幀內不透明像素的相符比例低於 50%，移除；其餘部分相符時只畫相符的像素。
- 上限 1024 個。超過時移除序號最小的，並在紀錄寫一行。地圖閒置時游標每個 tick 31 至 44 次呼叫、戰鬥佈陣另有約 17 次（審查實測），去重後遠小於上限。

## 5. 畫面合成

### 5.1 取樣時機

`Frame` 的快照在滑鼠輪詢點取（`d.Mouse.Polls` 增加的時刻，遊戲此時回到等輸入的迴圈）。tick 邊界取樣時，游標矩形完整繪出的比例只有 9/30（均勻取樣）至 28/40（每 636,085 道指令），會出現半個游標。滑鼠 100 毫秒內沒有輪詢（動畫、載入）時，退回牆鐘 100 毫秒的快照。

### 5.2 基底層

`640x480` 索引色畫面經 `Machine.PlanarRGB`（含 AC 到 DAC 的對應）轉 RGB，整數倍放大（最近鄰，或選用的平滑濾鏡）。

### 5.3 疊層

每個戳記：

1. 期望像素 `E(i, j)` 與目前 VRAM `V(x+i, y+40+j)` 比對（`y` 是遊戲座標）。
2. 對每個不透明的原版像素：`V ＝ E` 就在 HD 層的 `S × S` 區塊畫 HD 像素（依 alpha 與基底層混合）；否則跳過。羽化區（輪廓外）只在其四鄰至少有一個相符的不透明像素時才畫。
3. 序號大的後畫。

### 5.4 調色盤淡入淡出

遊戲淡入淡出只改 DAC，不改索引（冷啟動 `1AD4:00C6` 呼叫 49 次，DAC 在第 474 萬至 477 萬道指令由 0 升到 255，審查實測）。HD 素材的顏色是畫出當下的調色盤。每個戳記記錄建立時的 DAC 快照 `D0`，合成時比對目前 DAC `D1`：

- 相同：HD 素材原色。
- `D1 ≈ k × D0`（每個 RGB 通道最小平方的比例 `k`，殘差每通道小於 4）：HD 像素乘上 `k`。
- 其他（調色盤循環、局部改色）：這一幀跳過該戳記的 HD，顯示基底層。

## 6. HD 素材契約（給美術處理）

| 項目 | 要求 |
|---|---|
| 格式 | PNG，RGBA，`S × w` 乘 `S × h`（`S ＝ 2`） |
| 輪廓 | 原版精靈的不透明區域（遮罩為 0 的像素，或無遮罩精靈的整個矩形）放大 `S` 倍後，alpha 必須是 255 |
| 邊緣 | 輪廓外最多 1 個原版像素（`S` 個 HD 像素）的羽化，alpha 可小於 255；超出的像素 alpha 為 0 |
| 色彩 | 與原版調色盤的色調一致；同一個角色在不同畫面使用同一張 |
| 座標 | 不平移、不縮放；圖內位置與原版逐像素對齊 |
| 內容 | 不加入原版沒有的元素、文字、浮水印 |
| 記錄 | `hd/provenance.tsv` 每張一行：`hash`、處理者、工具與版本、日期、方法紀錄的連結 |

`tools/hd/validate.py` 檢查前四項。

## 7. 驗收

| 項目 | 方法 | 預期 |
|---|---|---|
| 不改變遊戲 | 同種子長跑，鉤子開與關，`report.tsv` 的畫面索引色雜湊序列逐位元相同 | 相同 |
| 素材缺漏回退 | 清空 `hd/` | 畫面等於基底層 |
| 被蓋住 | 用 `docs/re/012` 探索節點中視窗開在精靈上的畫面 | 被蓋住的部分顯示視窗，不露出 HD 精靈 |
| 被還原 | 開關選單，保存區還原之後 | HD 精靈區域回到背景，沒有殘影；游標移動 100 次後佇列中的游標戳記數為 1 |
| 淡入淡出 | 冷啟動到新遊戲的淡入段 | HD 亮度隨 DAC 改變，不先全亮 |
| 清冊一致 | 冷啟動到新遊戲與探索節點的鉤子紀錄中，未識別雜湊列在 `unknown.tsv`，不當錯誤 | 已知畫面的識別率報告（以雜湊數與出現次數計） |
| 雜湊一致 | 離線與執行期的 `Hash` 對同一批 PNG 與記憶體精靈 | 逐一相同（至少 `SPOINT.MRG` 52 張、`KOMA.MRG` 72 張） |
| 效能 | 一個核心上疊 512 個戳記的每幀時間 | 小於 4 ms |
| 目視 | 原圖與 HD 並排截圖，由使用者過目 | 使用者確認才通過 |

## 8. 推論等級、玩家垂直路徑與已知差異

| 項目 | 等級 |
|---|---|
| 精靈貼圖進入點參數位置與資料長度公式 | confirmed（審查用 IDA 與 `-call-args` 驗證，與 `docs/re/006` 一致） |
| 取樣 2 萬次呼叫中 x 非 8 的倍數、旗標非 0 的次數為 0 | confirmed（位移路徑與旗標路徑未驗證，列在第 9 節） |
| 串流解碼函式在進入與返回的行為 | 強推論（`docs/re/009` 第 4.2 節的簽章；返回路徑靜態檢查） |
| 24x24 快取貼圖路徑 | 強推論（冷啟動 6 次呼叫，槽號對應項目號的推定） |
| 失效規則 2 讓游標殘影消失 | 假說（未實測） |
| 玩家垂直路徑 | 標題、地圖、顧問對話、系統選單、戰鬥佈陣已有畫面收據（`docs/re/012`）；戰鬥進行、商店、結算畫面的繪圖路徑未取樣 |

與原版的差異：畫面多了 HD 疊層與倍率；遊戲邏輯、存檔、輸入不變。存檔影響：無（疊層不寫遊戲資料）。權利邊界：`hd/` 的 PNG 是衍生物，只放 private repo，不放進發行包以外的任何位置；發行包是否帶 HD 素材由使用者另行決定。

失敗模式：鉤子位址與映像不符（SHA-256 綁定，`docs/spec/003` 第 2 節）時不載入鉤子；PNG 與清冊不一致時拒絕該筆並記錄；戳記佇列溢出時丟棄最舊並記錄。

工具版本：`hdlib`（`tools/hd`，基準演算法 v1）、dosgolem 分支 `hr`（實作時固定 commit）。

## 9. 未解

- XOR 線框動畫（`docs/re/009` 第 3 節）：被 XOR 的像素比對失敗，HD 在線上被切開，線本身是低解析度。接受為已知差異。
- 半透明板面（以圖樣填滿）蓋住精靈：同上，只畫相符的像素。
- 文字顏色與精靈像素同色時，文字被 HD 覆蓋的像素（最多每個字數個像素）：接受為已知差異，量化未做。
- 精靈的位移路徑（x 非 8 的倍數）與旗標非 0 的路徑：未觸發，未驗證。
- 游標 40x32 的素材來源與轉換規則（`docs/re/009` 第 10 節）。
- 地圖類（`PXZ`、`GMAP.PXS`）的期望像素：取自清冊 PNG 的索引色；PXZ 只寫 span，未寫的像素是 VRAM 先前的內容，驗證要排除透明像素（索引 16）。
- 美術處理的規模：清冊 615 張中實際出現在畫面上的、重複內容的比例，由記錄模式量測。
- 平滑濾鏡的基底層與 HD 疊層混用時，交界處的視覺差異。
- 停止線：任何需要寫入遊戲記憶體、改變遊戲邏輯、或把 HD 素材放進公開發行的作法，退回 DRAFT 並問使用者。
