# 004 HD 圖像替換機制（疊層）

狀態：DRAFT（2026-10-03）。審查通過後才標 READY，READY 之前不寫正式實作。
日期：2026-10-03
前置：`docs/re/006-image-and-container-formats.md`（格式與 615 張清冊）、`docs/re/009-draw-primitives-DRAFT.md`（繪圖原語與呼叫慣例，DRAFT）、`docs/spec/003-runtime-and-frontend.md`、`AGENTS.md` 第 8 節。
實作位置：`workplace/dosgolem` 本地分支 `hr` 的 `apps/hr/hd`；素材放本 repo 的 `hd/`（private repo，`AGENTS.md` 第 2 節）。

## 1. 目標與不變條件

- HD 只影響呈現。遊戲邏輯、座標、尺寸、記憶體與 VRAM 內容不變；遊戲看到的永遠是原版的 `640x400` 索引色畫面。
- 沒有 HD 素材（缺檔、雜湊不在清單、驗證失敗）的位置，顯示原版像素的放大，不報錯。
- 原版檔案不複製進 `hd/`，`hd/` 只放美術處理後的 PNG 與記錄；PNG 是原版素材的衍生物，repo 維持 private（`AGENTS.md` 第 2 節）。
- 輸出倍率 `S` 固定為 2 的整數倍；素材以 2 倍製作（`1280x800` 遊戲區），前端依視窗再縮放。

## 2. 為什麼用「驗證式疊層」

遊戲直接寫 VRAM（planar，`docs/re/009`）。精靈被後來的視窗蓋住、被保存背景還原、與其他精靈重疊時，VRAM 會回到別的內容；若 HD 層記住「這裡有一張圖」就永遠畫它，被蓋住的部分會露出來。所以每個 HD 戳記在每一幀都和 VRAM 當下的內容比對，只在 VRAM 像素與該精靈原版像素相同的位置畫 HD 像素：被蓋住或被還原的部分自動不畫，不需要追蹤保存與還原事件。

## 3. 資料流

```text
遊戲執行 ──(位址鉤子)──> 戳記佇列 {種類, x, y, w, h, 資產雜湊, 期望像素(索引色), 序號}
                                  │
每一幀：VRAM(索引色 640x480) ──> 基底層：整數倍放大（最近鄰，或選用的平滑濾鏡）
                                  │
戳記 ∘ HD 素材(RGBA, S 倍) ──驗證──> 疊在基底層上（只畫與 VRAM 相符的像素）
```

### 3.1 位址鉤子（`apps/hr/hd`）

在每道指令前檢查 `CS:IP` 是否為登錄的進入點（一個 65536 位元的點陣圖先篩偏移，再比段）。鉤子只讀記憶體與暫存器，不寫入，不改變遊戲執行。

| 進入點（執行期） | IDA | 取得 | 戳記 |
|---|---|---|---|
| `1C57:0022` | `2B47:0022` | 堆疊 `[bp+6]` 旗標、`+8` x、`+0Ah` y、`+0Ch/0Eh` 精靈遠指標（`docs/re/009` 第 4.1 節；進入點尚未 `push bp` 時位置要換算） | 若旗標為 0：讀 5 bytes 標頭（寬 w、高 h、旗標 bit 0 ＝ 遮罩），資料長度 `5 ＋ (w÷8) × h × (4 ＋ 遮罩)`；雜湊標頭加資料；期望像素由平面資料解出（含遮罩）。旗標非 0 不畫，不產生戳記 |
| 串流解碼（`1FA2:0414`、`1FA2:066A`、`259F:0005`、`20C2:25A1`、`234A:000A`） | `2E92:0414`、`066A`、`348F:0005`、`2FB2:25A1`、`323A:000A` | 進入時串流指標與 VRAM 偏移；返回時（鉤子掛返回位址）讀 VRAM 該矩形 | 背景、頭像、地圖：期望像素取自解碼完成後的 VRAM 矩形；雜湊取壓縮串流（含長度）或檔案識別 |
| `3268:1155`（24x24 快取貼圖） | `3268:1155` | 槽號、x、y | 期望像素由快取讀出（第 7 節未解） |

保存與還原（`1F69:000E`、`00B5`、`0169`）不需要鉤子：驗證式疊層在還原之後的下一幀自然讓相符檢查失敗。

### 3.2 資產識別

資產雜湊是 SHA-256（前 16 個十六進位字元）。精靈與串流的雜湊規則由 `docs/re/006` 的清冊工具（`tools/img/`）產出，`hd/catalog.tsv` 的欄位：

| 欄位 | 內容 |
|---|---|
| `id` | `檔名:項目號`，例如 `SPOINT.MRG:14` |
| `hash` | 記憶體內精靈（標頭加資料）或壓縮串流的雜湊 |
| `w`、`h` | 原版像素尺寸 |
| `kind` | `sprite`、`mask`、`bg`、`face` 等 |
| `hd` | 對應的 HD PNG 相對路徑（空 ＝ 尚無） |

相同內容的精靈有相同的雜湊，共用一張 HD 圖（`docs/re/009` 第 6.4 節）。載入時掃描 `hd/` 內容與 `catalog.tsv` 的一致性；PNG 不存在或尺寸不是 `S × w` 乘 `S × h` 就拒絕該筆並在紀錄寫一行。

## 4. HD 素材契約（給美術處理）

| 項目 | 要求 |
|---|---|
| 格式 | PNG，RGBA，`S × w` 乘 `S × h`（`S ＝ 2`） |
| 輪廓 | 原版精靈的不透明區域（遮罩為 0 的像素，或無遮罩精靈的整個矩形）放大 `S` 倍後，alpha 必須是 255 |
| 邊緣 | 輪廓外最多 1 個原版像素（`S` 個 HD 像素）的羽化，alpha 可小於 255；超出的像素直接丟棄 |
| 色彩 | 與原版調色盤的色調一致（以原版圖的色彩分布為基準，不要求逐色相同）；同一個角色在不同畫面使用同一張 |
| 座標 | 不平移、不縮放；圖內位置與原版逐像素對齊 |
| 內容 | 不加入原版沒有的元素、文字、浮水印 |
| 記錄 | 每張圖一行 `hd/provenance.tsv`：`id`、處理者、工具與版本、日期、對照原圖的雜湊 |

## 5. 驗證與繪製

每一幀、每個戳記：

1. 取出戳記的期望像素 `E(i, j)`（索引色或透明）與目前 VRAM `V(x+i, y+j)`。
2. 對每個不透明的原版像素 `(i, j)`：若 `V ＝ E`，在 HD 層的 `S × S` 區塊畫 HD 像素（依 alpha 與基底層混合）；否則跳過。羽化區（輪廓外）只在其四鄰至少有一個相符的不透明像素時才畫，避免殘影漂在被蓋住的位置。
3. 後面的戳記（序號大者）後畫，與繪製順序一致。
4. 戳記保存到被檢查證實全部不符（整張被蓋住或被還原）為止，連續 N ＝ 3 幀全不相符就移除。

戳記佇列有上限（預設 512）。超過時丟棄最舊的，並在紀錄寫一行。

遊戲區的游標（`docs/re/009` 第 8.2 節）由遊戲自己繪製與還原；它也走 `1C57:0022`，同一套機制處理。

## 6. 驗收

| 項目 | 方法 | 預期 |
|---|---|---|
| 不改變遊戲 | 同種子長跑，鉤子開與關，`report.tsv` 的畫面雜湊（VRAM 索引色）逐位元相同 | 相同 |
| 素材缺漏回退 | 清空 `hd/` | 畫面等於基底層 |
| 被蓋住 | 腳本把視窗開在已貼圖的精靈上（用 `docs/re/012` 探索到的節點） | 被蓋住的部分顯示視窗，不露出 HD 精靈 |
| 被還原 | 開關選單，保存背景還原後 | HD 精靈區域回到背景，沒有殘影 |
| 清冊一致 | `catalog.tsv` 的雜湊在冷啟動到新遊戲的鉤子紀錄中全部可解 | 未知雜湊列出，不當錯誤 |
| 效能 | 一個核心上疊 512 個戳記的每幀時間 | 小於 4 ms |
| 目視 | 原圖與 HD 並排截圖，由使用者過目 | 使用者確認才通過 |

## 7. 未解

- 3268 段 24x24 快取貼圖的期望像素取得方式；若快取只存資料不含標頭，雜湊以資料為準。
- 串流解碼進 VRAM 時，返回位址的鉤子需要確認不會被遊戲自己的堆疊操作影響（例如函式不返回）。
- 精靈在平面資料上做位移（x 非 8 的倍數）的路徑（`2B47:01E9`）：取樣的 4787 個呼叫都沒觸發，位移路徑的期望像素未驗證。
- 非 `2B47:0022` 的繪製：線條、字形、板面（`docs/re/009` 第 3 節）。它們不被替換，只出現在基底層；HD 精靈蓋在上面時，字形與線條仍是低解析度。
- 平滑濾鏡的基底層與 HD 疊層混用時，交界處的視覺差異。
- 美術處理的規模：清冊 615 張，其中實際出現在畫面上的、重複內容的比例未量測。
