## 1. 範圍與不變條件

範圍：`MAIN.EXE` 遊戲畫面中，經 `2B47:0022` 精靈貼圖、串流解碼進 VRAM、24x24 遮罩精靈快取三條路徑繪出的圖像。
排除：線條、字形、板面圖樣（`docs/re/009` 第 3 節）；它們只出現在基底層，HD 精靈蓋在它們上面時仍是低解析度。`PXZ` 戰場地圖（只寫 span）第一版不替換。`OP.EXE`、`END.EXE`。

- HD 只影響呈現。遊戲邏輯、座標、尺寸、記憶體與 VRAM 內容不變；遊戲看到的永遠是原版的 `640x480` 索引色畫面（遊戲區 `640x400`，第 40 至 439 列）。
- 沒有 HD 素材（缺檔、雜湊不在清單、驗證失敗）的位置，顯示原版像素的放大，不報錯。
- 原版檔案與原版解析度的解碼內容不進 `hd/`：`hd/` 只放美術處理後的 PNG 與記錄。執行期需要的原版像素（期望像素）由執行層從玩家自備的原版資料即時解出（第 3 節的解碼器），不是從 `hd/` 讀。PNG 是原版素材的衍生物，repo 維持 private。
- 輸出倍率 `S` 固定為整數；素材以 `S ＝ 2` 製作（`1280x800` 遊戲區）。其他倍率的素材放不同目錄，不混用。

## 2. 為什麼用「驗證式疊層」

遊戲直接寫 VRAM（planar）。精靈被後來的視窗蓋住、被保存背景還原、與其他精靈重疊時，VRAM 會回到別的內容。HD 層若只記「這裡有一張圖」就永遠畫它，被蓋住的部分會露出來。所以每個戳記在每一幀都和 VRAM 當下的內容逐像素比對，只在 VRAM 像素等於該精靈原版像素的位置畫 HD 像素：被蓋住的部分自動不畫。

逐像素比對有兩個已量測的缺口，所以另有失效與遮蔽規則（第 4 節）：游標移走後，舊位置仍有約 15%（42／272）不透明像素與背景同色；窗格以網點蓋住精靈時，相符比例在 48% 與 60% 之間擺動，所以不能用比例當移除條件。

## 3. 識別與期望像素

### 3.1 雜湊

`SHA-256( u16le 寬 ∥ u16le 高 ∥ 索引色位元組 )`，全部 64 個小寫十六進位字元。索引色位元組逐列、每像素一個位元組，0 至 15 是顏色（遊戲的 EGA 像素值，`Machine.Planar` 的輸出，不是 DAC 索引），16 表示透明（遮罩為 0）。

- 離線：`tools/hd/catalog.py` 對解碼 PNG（索引色，16 為透明）計算，寫入 `hd/catalog.tsv`。
- 執行期：`apps/hr/hd` 的 `Hash(w, h, idx)`，同一定義。已有跨語言測試：Go 解碼全部 `*.MRG`（除 `ESPMES.MRG`）的 553 個非空項目（含 LZSS 壓縮與 packed 4bpp 項目，`SPOINT`、`KOMA`、`BC32`、`ITEM`、`FACE` 等）的雜湊與清冊逐一相同，另有一個固定測試向量。GS、PCX、GRP、BIN、PXS、PXZ 的 Go 解碼器未做。

### 3.2 解碼器（`apps/hr/hd`）

期望像素與雜湊都從遊戲交給繪圖函式的資料即時解出，與是否經檔案、壓縮無關：

| 來源 | 解碼 |
|---|---|
| 記憶體內精靈（`2B47:0022`、`2378:1155`） | 5 bytes 標頭（u16 寬、u16 高、u8 旗標）加逐列平面資料；已實作（`DecodePlanarSprite`）。24x24 快取直接讀 `cs:[0Eh ＋ 槽號 × 168h]`（程式碼段 `2378`，無標頭，24x24，遮罩），載入狀態檔後 `112A` 沒被觀察到時仍可讀 |
| `2E92:0414`（旗標 0）、`2E92:066A`（遮罩在列首） | 從遠指標起讀 LZSS 串流：u32 解壓長度，其後 LZSS（`docs/re/006` 第 5 節，1024 bytes 環、起點 `0x3BE`），解出標頭加平面資料，依旗標選版面（`p0..p3` 或 `mask, p0..p3`）。壓縮長度不在標頭，解到解壓長度為止 |
| `348F:0005`（`259F:0005`） | 收到的是**已解壓**的 packed 4bpp 資料（標頭加每像素 4 位元），不是壓縮串流（審查實測進入時資料為 `80 00 A0 00 80`） |
| `GMAP.PXS`（`2FB2:25A1`，執行期 `20C2:25A1`） | 整張 `640x400` 矩形，返回時由 VRAM 讀索引色，整張矩形的雜湊與清冊逐位元相同（審查實測），不需按參數識別 |

`PXZ` 戰場地圖與 `FACE` 以外的串流若解碼失敗（資料不足、長度不符），該次呼叫不產生戳記並計數，不中止遊戲。

### 3.3 `hd/catalog.tsv`

| 欄位 | 內容 |
|---|---|
| `hash` | 3.1 的雜湊 |
| `id` | `檔名:項目號`；相同內容合併成一列，`id` 以分號列出全部 |
| `w`、`h` | 原版像素尺寸 |
| `kind` | `sprite`、`face`、`bg`、`map`、`bg256` |
| `pal` | 該素材的參考調色盤名稱（`docs/re/006` 第 8 節；MRG 精靈用 `MAIN`，`GS` 用同名 `.RGB`） |
| `hd` | 對應的 HD PNG 相對路徑（空 ＝ 尚無） |
| `singleton` | `1` 表示同時只會有一個（游標），見 4.2 |

調色盤表 `hd/palettes.tsv`（名稱、16 個 RGB）是 DAC 色值，原版內容的一小部分，放在 private repo 的 `hd/`，不進發行包。

游標（40x32，工作副本 `DS:1BD1`）不在清冊內：它由 `28EB` 段在執行期從 `CURSOR.MRG`（24x24）轉換產生。執行期的記錄模式（`-hd-record`）把未識別的雜湊、矩形、出現次數寫成 `hd/unknown.tsv`，游標的 HD 素材以雜湊加入清冊並標 `singleton`。

## 4. 戳記

### 4.1 掛鉤（`apps/hr/hd`）

`apps/hr/runtime` 的 `stepBatch` 不經 `oracle`，所以 `apps/hr/hd` 自備掛鉤表：一個 65536 位元的偏移點陣圖先篩，命中再比段與偏移；回呼只讀記憶體與暫存器，不寫入，不改變遊戲執行。VRAM 讀回一律用 `Machine.Planar()`，不用 `Read8`（planar 讀有 latch 副作用）。進入點的堆疊（far call，尚未 `push bp`）：`[SP]` 返回 IP、`+2` 返回 CS，參數從 `+4` 起。

| 進入點（執行期） | IDA | 參數 | 動作 |
|---|---|---|---|
| `1C57:0022` | `2B47:0022` | `+4` 旗標、`+6` x、`+8` y（遊戲座標，VRAM 列加 40）、`+0Ah` 精靈偏移、`+0Ch` 精靈段 | 旗標為 0：解碼、雜湊、建戳記。旗標非 0 不畫，不建 |
| `2378:1155` | `3268:1155` | 槽號、x、y | 讀槽的內容建戳記（24x24 遮罩） |
| `1FA2:0414`、`1FA2:066A` | `2E92:0414`、`066A` | 壓縮串流遠指標、VRAM 偏移 | 進入時解碼串流，建戳記（位置取自偏移與標頭尺寸） |
| `259F:0005` | `348F:0005` | 已解壓資料遠指標、VRAM 偏移 | 進入時解碼，建戳記 |
| `20C2:25A1` | `2FB2:25A1` | 檔案 handle、VRAM 偏移 | 返回時讀 VRAM 整張矩形，雜湊，建戳記 |
| `1F69:0169`、`1F69:00B5`、`2378:139D` | `2E59:0169`、`00B5`、`3268:139D` | 還原（保存區遠指標；x÷8、y、保存區遠指標；槽號） | 返回後重驗相交的戳記（規則 R2） |

返回鉤子：進入時記下返回位址與 `SP`；`CS:IP` 回到返回位址且 `SP` 等於進入時的 `SP ＋ 4`（far return 彈出兩個字組）才觸發。各串流函式是正常 `retf`（審查查過，沒有不返回的路徑）；SP 對不上的情形（函式被打斷）就丟棄這一筆。

### 4.2 戳記佇列與規則

戳記欄位：種類、x、y、w、h、雜湊、期望像素（索引色，16 為透明）、序號、是否有 HD。

- **去重**：以 `(x, y, w, h, 雜湊)` 為鍵，同鍵的新戳記取代舊的並取新序號。
- **singleton**：清冊標 `singleton` 的雜湊（游標）同時只留最新一個。
- **R1 蓋過**：串流解碼戳記（`bg`、`face`、`map`）建立時，移除矩形被它完全包含的舊戳記（該區域已被重繪）。
- **R2 還原重驗**：還原呼叫返回後，與還原矩形相交的戳記立即重驗；重驗後不透明像素相符比例低於 70% 的移除，其餘保留。審查實測：還原矩形 `(192, 200, 144x168)` 完全包含 `SPOINT_021`，還原後 593／593 相符，所以包含關係本身不能當移除條件。還原矩形取自保存區標頭（x÷8、y、w÷8、h，`docs/re/009` 第 8.1 節）；游標的保存矩形完全包含舊游標戳記（95／95，含 `x ＝ 632`、`y ＝ 399` 的邊緣，審查實測）。
- **不依比例移除**：沒有「相符比例過低就移除」的規則。逐像素只畫相符的位置，比例低時整個戳記實際上不畫但仍保留，避免網點覆蓋時誤刪（審查實測 48% 至 60% 擺動）。
- **LRU**：上限 1024 個，超過時移除序號最小的並在紀錄寫一行。去重後地圖閒置時遠小於上限（游標每個 tick 31 至 44 次呼叫、戰鬥佈陣另有約 17 次，審查實測）。

## 5. 畫面合成

### 5.1 取樣時機

`Frame` 的快照在**滑鼠輪詢指令剛執行完**的那一刻取（`stepBatch` 逐指令檢查 `d.Mouse.Polls` 的長度，不是批次邊界）。審查實測：批次邊界（2048 道指令）取樣時游標完整的比例只有 8% 至 9%，輪詢指令剛執行完時是 158／159。快照上限約 120 Hz。滑鼠 100 毫秒內沒有輪詢（動畫、載入）時退回牆鐘 100 毫秒的快照；此時戳記要等其貼圖呼叫返回後才參與合成（審查實測：戰鬥開場動畫有 43% 至 54% 的步數落在貼圖途中）。

### 5.2 基底層

`640x480` 索引色畫面經 `Machine.PlanarRGB`（含 AC 到 DAC 的對應）轉 RGB，整數倍放大（最近鄰，或選用的平滑濾鏡）。

### 5.3 疊層

依序號由小到大處理每個戳記（含沒有 HD 的戳記）：

1. 期望像素 `E(i, j)` 與目前 VRAM `V(x+i, y+40+j)` 比對。
2. 對每個不透明的原版像素：`V ＝ E` 時，該戳記有 HD 就在 HD 層的 `S × S` 區塊畫 HD 像素（依 alpha 與基底層混合）；**沒有 HD 的戳記則把該區塊還原成基底層**（遮蔽先序戳記的 HD。審查實測：游標在 SPOINT 上方且游標沒有 HD 時，272 個不透明像素中有 30 至 58 個會被下方的 HD 蓋掉）。
3. 羽化區（輪廓外）只在其四鄰至少有一個相符的不透明像素時才畫。

### 5.4 調色盤淡入淡出與改色

遊戲淡入淡出只改 DAC，不改索引。HD 素材的顏色是它的參考調色盤（`pal` 欄）的顏色。審查實測：新遊戲地圖的 `SPOINT` 14 個與 `EXIST` 在 DAC 全 0 時建立（淡入在第 4804.6 萬至 4807.6 萬道指令），標題的 `GMAP` 也在 DAC 全 0 時畫，所以不能用「建立時的 DAC」當基準。基準是參考調色盤，每幀對每個戳記的參考調色盤算一個比例：

- 以該戳記實際用到的索引為準，`D_now[i] ≈ k × P_ref[i]`（每個 RGB 通道最小平方的比例 `k`，殘差每通道小於 4）：HD 像素乘上 `k`（`k ＝ 1` 即原色）。
- 殘差超過容許值（調色盤循環、局部改色）：該幀跳過該戳記的 HD，顯示基底層。

審查實測：比例模型與冷啟動淡入吻合。

## 6. HD 素材契約（給美術處理）

| 項目 | 要求 |
|---|---|
| 格式 | PNG，RGBA，`S × w` 乘 `S × h`（`S ＝ 2`） |
| 輪廓 | 原版精靈的不透明區域（遮罩為 1 的像素，或無遮罩精靈的整個矩形）放大 `S` 倍後，alpha 必須是 255 |
| 邊緣 | 輪廓外最多 1 個原版像素（`S` 個 HD 像素）的羽化，alpha 可小於 255；超出的像素 alpha 為 0 |
| 色彩 | 與參考調色盤的色調一致；同一個角色在不同畫面使用同一張 |
| 座標 | 不平移、不縮放；圖內位置與原版逐像素對齊 |
| 內容 | 不加入原版沒有的元素、文字、浮水印 |
| 記錄 | `hd/provenance.tsv` 每張一行：`hash`、處理者、工具與版本、日期、方法紀錄的連結 |

`tools/hd/validate.py` 檢查前四項。

## 7. 驗收

| 項目 | 方法 | 預期 |
|---|---|---|
| 不改變遊戲 | 同種子長跑，掛鉤開與關，`report.tsv` 的畫面索引色雜湊序列逐位元相同 | 相同 |
| 雜湊一致（已有部分） | Go 與 `catalog.py` 對同一批資料 | `*.MRG` 553 個非空項目（含 LZSS 與 packed4）已逐一相同；GS、PCX、GRP、BIN、PXS 的 Go 解碼器未做 |
| 識別率 | 冷啟動到新遊戲、戰鬥佈陣（探索節點 79 至 95）的掛鉤紀錄 | `2B47:0022` 路徑全部識別（審查實測冷啟動 15／15、戰鬥佈陣 171／171）；未識別的列在 `unknown.tsv` |
| 素材缺漏回退 | 清空 `hd/` | 畫面等於基底層 |
| 被蓋住 | 探索節點中視窗開在精靈上的畫面 | 被蓋住的部分顯示視窗，不露出 HD 精靈 |
| 還原 | 開關選單後 | 還原後仍相符的精靈保留 HD；被還原掉的移除；游標移動 100 次後佇列中的游標戳記數為 1，沒有殘影 |
| 遮蔽 | 游標移到沒有 HD 的位置下方有 HD 精靈的地方 | 游標像素不被 HD 蓋掉 |
| 淡入淡出 | 冷啟動到新遊戲的淡入段 | `SPOINT`、`EXIST`、`GMAP` 的 HD 亮度隨 DAC 改變，不先全亮、不永遠不顯示 |
| 快照完整 | 逐快照檢查游標矩形是否完整 | 完整的比例大於 95%（目前批次邊界取樣 8%） |
| 效能 | 一個核心上疊 512 個戳記的每幀時間 | 小於 4 ms（未量測） |
| 目視 | 原圖與 HD 並排截圖，由使用者過目 | 使用者確認才通過 |

與原版的差異：畫面多了 HD 疊層與倍率；遊戲邏輯、存檔、輸入不變。存檔影響：無（疊層不寫遊戲資料）。權利邊界：`hd/` 的 PNG 與調色盤表是原版素材的衍生物，只放 private repo；發行包是否帶 HD 素材由使用者另行決定。

失敗模式：掛鉤位址與映像不符（SHA-256 綁定，`docs/spec/003` 第 2 節）時不載入掛鉤；PNG 與清冊不一致時拒絕該筆並記錄；解碼失敗不建戳記並計數；戳記佇列溢出時丟棄最舊並記錄。

工具版本：`hdlib`（`tools/hd`，基準演算法 v1）、dosgolem 分支 `hr`（實作時固定 commit）、Go 1.26.7。

## 9. 未解

- XOR 線框動畫（`docs/re/009` 第 3 節）：被 XOR 的像素比對失敗，HD 在線上被切開，線本身是低解析度。接受為已知差異。
- 半透明板面蓋住精靈：只畫相符的像素。
- 文字顏色與精靈像素同色時，文字被 HD 覆蓋的像素（最多每個字數個像素）：接受為已知差異，量化未做。
- 精靈的位移路徑（x 非 8 的倍數）與旗標非 0 的路徑：未觸發，未驗證。
- 游標 40x32 的素材來源與轉換規則（`docs/re/009` 第 10 節）。
- `PXZ` 戰場地圖（只寫 span）：第一版不替換；之後要有 Go 的 PXZ 解碼器。
- LZSS 與 MRG 各版面的 Go 解碼器（第 3.2 節）已實作並以清冊驗證；`2E92:0414` 路徑未取樣；GS、PCX、GRP、BIN、PXS、PXZ 的解碼器未做。
