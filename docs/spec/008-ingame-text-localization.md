## 3. 設計

### 3.1 L0 語言層（dosgolem 通用能力）

- 解析順序：暫存層（`Scratch`）、語言層（新增 `DOS.LangDir`）、原版目錄（`Root`）。語言層缺檔時回退原版。其餘規則（只認 basename、大小寫不分、8.3 截斷）沿用。暫存層優先於語言層是對的：玩家存檔蓋過一切。
- **`LangDir` 在 `Session.Open` 綁定一次，執行中不變。** `LangDir` 為空時行為與現況完全相同（零成本退路）。不提供執行中切換：字模 handle 常開，MES 換了而字模沒換會畫出無關的字（審查 A B1、審查 B B2）。換語言的唯一動作是重新啟動前端。
- **寫入模式開語言層的檔：明文拒絕**（回 DOS 存取被拒的錯誤碼），不走 `scratchCopy`。理由：複製進暫存層後，暫存層永遠優先，語言包會失效；遊戲對這些檔一律唯讀開檔（023 第 5 節），拒絕不改變正常路徑。`AllowFileWrites`（`dos.go:497`）白名單不收語言層的檔。
- `find.go` 的 `searchFor` 目錄順序改為 `Root`、`LangDir`、`Scratch`，後者覆蓋前者。`MAIN.EXE` 不呼叫，但通用能力要補，並加測試。
- 其他 `resolve` 呼叫者（`exec.go:224`、`:369`、`dosinfo.go:164`、`:272`、`font.go:201`、`fileops.go:147`、`:187`、`files.go:419`）插入語言層後行為一致，各列入測試。
- **狀態檔語意**：`dosState` 新增 `LangDir`（gob 向後相容，舊檔視為空；`dosStateVersion` 不升，因為欄位缺省值等價於舊行為）。`LoadState` 比對狀態檔記錄的 `LangDir` 與目前 Session 的 `LangDir`，**不同就明確拒絕載入**，錯誤訊息點名兩個值；handle 的絕對路徑照舊（它們指向語言包內或原版目錄的檔）。因此：語言層與字模的驗證一律從冷啟動起跑；語言包 Session 存下的診斷狀態檔只能在同一 `LangDir` 載入，換機器或刪包後載入會明確失敗，不會悄悄用到別的包。`apps/hr/runtime/session.go:259` 的 `Options.LangDir` 是傳遞點。
- **開檔層報告**：`d.Opened` 與 `OnOpen` 除了 basename，另報命中哪一層（`scratch`、`lang`、`root`）。診斷（`docs/spec/005` 的 `info.txt`）新增三項：`LangDir` 的值、語言包 manifest 的 SHA-256、最近開啟的檔與其命中層（第 11 節）。
- 通用性：位址與檔名都不在 dosgolem 內。判準「換一支 binary 之後這段還成立嗎」成立。

### 3.2 語言包與建置器

- 語言包是建置產物，位置 `<資料目錄>/l10n-packs/<code>/`，內容：被翻譯的資料檔（`SYSTEM.MES` 等，序列化後的檔）、`CFONT.15`（原版為底加補丁）、`manifest.json`。語言包含原版位元組（`keep` 項目、未動的字模），所以**只存在使用者機器的資料目錄，不進版控，不進發行包**；`leakscan` 對 `l10n-packs` 路徑與同名檔判洩漏。
- **建置在玩家機器上執行**，輸入是玩家自備的原版檔案加譯文清冊（第 3.3 節）加字模補丁（第 3.4 節）。建置器是 `apps/hr/l10n`，前端內嵌。觸發：前端啟動時，若 `-ingame-lang <代碼>`（或環境變數 `HR_INGAME_LANG`）指定了語言，且語言包不存在或 manifest 與輸入不符，先建置（進度印標準錯誤並顯示在 toast，失敗訊息點名項目），建置成功才以該 `LangDir` 開 Session；失敗則遊戲內文字維持原版，記一行，不阻擋遊戲。清冊與補丁的尋找順序：旗標 `-l10n`、環境變數 `HR_L10N`、執行檔旁的 `l10n/`、資料目錄的 `l10n/`。預設發行包不附清冊（第 12 節 U1、U3），所以預設只有開發機能建置。
- 建置步驟：
  1. 核對每個原版輸入的 SHA-256（來源 `source-inventory.tsv`），不符即失敗，不猜測套用。
  2. 解析七個資料檔，逐項以清冊覆蓋譯文；沒有譯文的項目與 `keep` 保留原位元組；序列化（第 3.5 節的序列化規則）；每個檔寫出。
  3. `CFONT.15`：以原版為底，把補丁記錄的自訂碼位置換成補丁的字模（第 3.4 節）。
  4. 寫 `manifest.json`：每個檔的 SHA-256 與位元組數、原版輸入雜湊、清冊整體雜湊與版本、補丁雜湊、建置器版本。
- 重現性：同一輸入兩次建置，所有輸出檔 SHA-256 相同。建置器只做整數與位元組運算，不做浮點光柵化（光柵化在開發側預先烘製，第 3.4 節），所以結果與平台無關。
- 啟用判定：`Session.Open` 以 manifest 驗證語言包（檔案存在、雜湊與大小相符、原版輸入雜湊相符）。驗證失敗：前端不啟用該語言包，記一行，遊戲內文字維持原版。`CheckRequiredFiles`（`session.go:232`）只驗原版，語言包另驗。
- 第三方可散布語言包（`LICENSE` 第 3 條 (c)）：清冊格式與建置器讓第三方在不含原版位元組的前提下產生並散布清冊與補丁，語言包本身由使用者在自己的機器上組出。

### 3.3 譯文清冊

位置 `l10n/<code>/<檔名>.tsv`（UTF-8，製表符分隔，跳脫 `\n`、`\t`、`\\`）：

| 欄 | 內容 |
|---|---|
| `id` | `*.MES`：`<檔名>#<項目索引>`；`ESPMES.MRG`：`ESPMES#<群組>.<子>`；`SHOPTAB.TBL`：`SHOPTAB#<記錄>.<欄位>` |
| `src_sha256` | 原項目位元組（以 NUL 切出的實體項目，去掉結尾 NUL，保留內部 `0A`）的 SHA-256 前 16 碼。只當版本綁定，不當保密手段（見下） |
| `text` | 譯文（UTF-8，`\n` 表示換行，`%` 序列原樣保留） |
| `status` | `candidate`、`accepted`、`keep`（保留原版位元組，不翻譯） |
| `acc_sha` | `accepted` 列接受時 `text` 的 SHA-256 前 16 碼；與目前 `text` 不符即視為 `candidate` |
| `by`、`batch`、`date` | 譯者（人或模型與版本）、批次、日期（比照 `hd/provenance.tsv`） |
| `note` | 譯者備註（譯名、語境），**禁止含原文**，由建置工具以第 3.9 節的內容判準檢查 |

- **措辭與風險**：清冊不含原文位元組。短項目（`SHOPTAB` 名稱欄、`SP.MES` 最短 7 bytes）的雜湊可由 Big5 字典暴力還原，所以逐項雜湊不是保密手段，只當版本綁定。清冊整體（尤其簡體等近似原文的譯文）視為原版文字的衍生物處理（`LICENSE` 第 3 條已承認譯文是衍生著作），不依賴雜湊的不可逆性。位元組數不寫進清冊（建置時由原版算）。
- 重複來源：`UWASA.MES` 110 項只有 10 種內容。建置報告列出所有「原項目位元組相同」的 id 群組（只列 id）；同群組的譯文必須相同，除非 `note` 明示例外。
- 合併規則：批次合併只能替換 `candidate` 列；改動 `accepted` 或 `keep` 列要明確旗標，並自動退回 `candidate`。
- 詞表 `l10n/<code>/glossary.tsv`：`term_key`（名稱位元組的 SHA-256 前 16 碼，名稱表以 020 第 2.3 節的段偏移定位）、`譯名`、`note`。建置器另從原版名稱表與對白切詞，產生只存在 `workplace/l10n-work/` 的 join 檔（`term_key` 對 `id` 與位置），供批次翻譯的全域一致性掃描使用；join 檔不進版控。
- 原文匯出：翻譯需要原文時，建置工具從使用者的原版檔案匯出到 `workplace/l10n-src/`（`id`、`src_text`，Big5 解碼），不進版控。

### 3.4 字碼與字模（L2）

本規格採**全面自訂碼**（對應第 12 節 U5 的 B 案；使用者若選 A 案，即共用字沿用原版字模，本節回到 DRAFT 修訂）：

- 所有簡體、日文、韓文譯文，凡不屬第 3.5 節單位元組白名單的字（含全形標點），一律配自訂碼。lead `0xE0` 至 `0xF9`、trail `0x40` 至 `0x7E` 與 `0xA1` 至 `0xFE`（每個 lead 157 碼，共 4082 碼）。理由：這個範圍在 `1676` 眼中全是成對路徑，trail 任何值都被正確消耗，不會觸發第 2 節「成對路徑吞換行」與「寬度邊界拆字」；字形全來自同一個光柵來源，風格一致；不需要把原版字模當作其他語言的字模來源。
- **保留碼位**：原版（硬編碼字串、段 4073 名稱、資料檔）已經在這個範圍使用的碼位不可配給譯文，其字模在語言包內維持原版。保留集合取（嚴格掃描 ∪ 寬鬆掃描 ∪ 所有資料檔與 `MAIN.EXE` 中 lead 在 `E0` 至 `F9` 的成對位元組），寫成 `reserved-codes.tsv`（只含碼位與來源，不含字形）。可用碼數 ＝ 4082 減保留集合落在該範圍的碼數；建置器計算並寫入報告。某語言的字集超過可用碼數，閘門失敗，不縮字集硬塞。
- 例外：繁體中文（`zh-TW`）改寫版的語言包（L1 試點使用）沿用原版 Big5 碼與原版字模，不配自訂碼，字集限於原版已用字。此時譯文走 `1676` 的單位元組路徑（lead `A1` 至 `DF`），第 2 節的兩個缺陷會生效，所以第 3.5 節對原碼字加「行尾字」檢查。
- 配碼確定性：字元依 Unicode 碼位排序，依序配給未保留的碼；同一個字集永遠得到同一組配碼。字集改變時整包重建（碼只存在語言包內）。
- **字模補丁**：開發側（Docker，`tools/l10n/`）由開放授權字型依固定參數預先烘製，輸出：
  - `glyphs-<code>.bin`：記錄 `(碼 u16 大端, 30 bytes 字模)`，依碼排序；
  - `charmap-<code>.tsv`：Unicode 碼位對自訂碼；
  - `SOURCE.txt`：字型檔名、SHA-256、版本、授權檔識別、光柵化工具與版本、固定參數（字面、像素大小、閾值、位移、裁切規則）、容器映像 ID。
  補丁只含 OFL 衍生字模，不含原版位元組。字型候選以 `docs/spec/006` 第 1 節登錄的 Noto Sans CJK（雜湊、字面、授權）為首選。補丁是否入版控與隨包發行屬使用者決定（第 12 節 U5），決定前只放 `workplace/`。
- 玩家端建置只做「原版 `CFONT.15` 加補丁」：補丁每筆的碼不得落在保留集合，被換的位置就地覆蓋 30 bytes，其餘位元組原樣保留。對原版字模只允許**整格原樣保留**，不做改圖、縮放、合成（`LICENSE` 第 2 條把點陣字型列為原版素材）。
- 光柵化方法（工具、閾值）在 L2 開工前以樣張實驗決定，結果寫成 DRAFT 小節並審查。15x15 光柵化對筆畫多的字可能糊；樣張閘門要含並排畫面（原版字模與補丁字模，`original` 與 `hd` 兩種 theme 各取一次；硬編碼說話者標籤用原版字模，必然與譯文字風格不同）。
- 補丁的決定性：開發側同一輸入兩次烘製，輸出 SHA-256 相同（同一容器映像內）。玩家端不重烘，所以不受跨平台浮點差異影響（macOS arm64 與 amd64 的光柵結果可能不同）。

### 3.5 預算與檢查（建置器強制，違反即失敗並列出全部違規項目的 id）

窗口表來源是 023 第 4 節的呼叫點普查，轉成 `tools/l10n/data/esp-windows.tsv`（`ESPMES` 每個項目所屬窗口類別，只含 id 與類別，來自 `espmap.txt`，不含文字，可入版控）加各檔的固定窗口：

| 檔案或類別 | 行寬（位元組） | 行數 |
|---|---:|---:|
| `ESPMES` 走 `01A3`、`06CF` | 30 | 4 |
| `ESPMES` 走 `07FE`（`#44.1`、`#44.2`、`#120.70`） | 62 | 8 |
| `ESPMES` 歸屬未知（`#122.165`、`#122.166`、`#122.168`） | 30 | 4 |
| `SP.MES` | 70 | 4 |
| `COUNTRY.MES` | 66 | 5 |
| `SYSTEM.MES`、`POWERMES.MES`、`UWASA.MES`（窗口歸屬未普查；`UWASA.MES` 走 `01A3`） | 原項目自己的最長行位元組數與行數為上限（原版 `SYSTEM.MES` 最長行 30、`UWASA.MES` 28、`POWERMES.MES` 30），且不超過 30 與 4 | 同左 |

行寬取窗口容量 `(w - 8) / 8` 再減一格，向下取偶數（雙位元組字成對，避開 `8 * si > 最大寬` 的邊界與 8 像素溢位，023 第 2.3 節）。

| 檢查 | 規則 | 依據 |
|---|---|---|
| 單項長度 | 編碼後位元組數 <= 511（含 `%` 展開後的最壞值，名稱欄位以 20 bytes 計） | 023 第 3 節（`3E41:0423` 容量 0x200 含 NUL，無長度檢查） |
| 行寬與行數 | 譯文每行（以 `0x0A` 或項目結尾分隔）位元組數 <= 上表行寬，行數 <= 上表行數。**超過就失敗，不交給引擎折行**（超過行數的後果是截斷，023 第 4.2 節）。自動折行：建置器對超寬行依單位寬度（半形 1、自訂碼 2）自動插入 `0x0A`，優先在標點之後折，不拆雙位元組對；折完仍超過行數則失敗 | 023 第 4 節 |
| 控制碼 | 不含 `0x00`；`0x0A` 只用於換行 | 020 第 7 節 |
| 空白 | **不含 `0x20`**（`01A3` 路徑會略過所有 `0x20`；窗口歸屬未知的項目一律當作走 `01A3`）。需要詞距的語言見第 3.6 節 | 023 第 3.1 節 |
| 單位元組白名單 | 只允許 `0x0A`、數字 `0x30` 至 `0x39`、`/`（`0x2F`）、`:`（`0x3A`）、大寫字母 `0x41` 至 `0x5A`，以及與原項目相同的 `%` 序列。其餘字元（含 `.`、`,`、`-`、`(`、`?`、小寫字母）一律用自訂碼的全形字，因為半形字模沒有它們（`0x21` 至 `0x2D` 等畫空白，小寫畫成另一組樣式的數字與大寫，020 第 3.3 節） | 020 第 3.3 節 |
| 佔位符 | 比對完整轉換規格（旗標、寬度、精度、長度修飾 `l`），個數、順序、型別與原項目相同；原版不支援位置參數。原項目的序列由建置器從原版解析 | 020 第 2.3 節；Borland 不支援 `%n$`：強推論 |
| 名稱欄位 | `SHOPTAB` 欄位 <= 20 bytes，尾端補 `0x20`；名稱之後的第一個位元組必須是 `00`，後 5 bytes 原樣不動 | 020 第 2.2 節 |
| 字碼 | 每個字都有字碼（單位元組白名單或第 3.4 節的自訂碼）；字集不超過可用碼數 | 第 3.4 節 |
| 原碼字的行尾（只適用 `zh-TW` 改寫版沿用原碼的字） | 行尾字 lead 在 `A1` 至 `DF` 且 trail 在 `E0` 至 `FC` 時，後面不得接 `0x0A`（會被吞，023 第 2.3 節）；lead 在 `A1` 至 `DF` 的字不得落在行寬邊界（第 31 位元組）而被拆行，建置器以預先折行的行寬（上表）避開 | 023 第 2.2、2.3 節 |

序列化規則：
- `*.MES`：偏移表依實體項目重算；**`COUNTRY.MES` 兩種模式**：identity 包（全部 `keep`，沒有任何譯文）原樣保留偏移表的 +2 偏差與最後偏移多 1；含任何譯文的包重算為精確偏移（譯文完整顯示，與原版項目 5 至 10 少讀第一個字不同，記為已知差異，第 12 節 U6）。
- `ESPMES.MRG`：依「相鄰偏移」判斷空群組，不把群組 45 至 115 當群組 116 的別名；外層保留 `N ＝ 126` 與 125 個偏移（沒有終止偏移）的原結構；群組 125、126 會通過載入端 `237B:04FE` 起的邊界檢查而讀到表外，這是原版缺陷，序列化不修。
- `SHOPTAB.TBL`：99 x 200 bytes 結構不變。
- identity 包必須與原檔逐位元組相同。

### 3.6 韓文詞距與英文（L3 的待實驗項，現在不導入）

- 韓文需要詞間空白，而 `0x20` 在 `01A3` 路徑被略過。假說：`020` 第 3.3 節說 `0x21` 等碼 `c-14 < 0x20` 時不取字模只畫空白，理論上可當「不會被略過的 8 像素空白」。這是假說，導入韓文前要做一次 probe（合成一行含該碼的對白，量畫面）。在此之前韓文不導入。
- 英文：原版半形字模沒有小寫字母與大多數標點（020 第 3.3 節）。020 第 4.4 節提出「雙字母字模」（把兩個 8x15 半形字模並排放進一格全形字模）。可用自訂碼 4082 減保留集合，小於 95 x 95 ＝ 9025，所以要先做雙字母頻率統計，只配常用組合。實驗內容與驗收在 L3 英文閘門之前補成獨立 DRAFT 小節，經審查才動手。在此之前英文不在導入範圍。

### 3.7 字模來源與授權

- 字模只用開放授權字型（OFL 或公有領域），逐一登記來源與授權。授權全文隨補丁保存（只取該段，斷言無 GPL，做法沿用 `docs/spec/006` 第 6 節）。Reserved Font Name 在發行前以原檔核對（`docs/spec/006` 的停止線同一條）。
- Copyleft 字型（GPL 等）對衍生字模與語言包的影響必須讀授權全文後判定，未判定前不使用。
- 不使用原版字型（`CFONT.15`）作為其他語言字模的來源。
- 簡體、日文（新字體）、韓文的涵蓋字集要對照該語言的譯文用字，缺字在烘製時失敗。

### 3.8 F4 與遊戲內語言

- **F4 不改變遊戲內語言。** `docs/spec/006` 第 5 節原寫「M10 的 L1 實作後，F4 同時設定遊戲內語言包」，本規格取代為：遊戲內語言由旗標 `-ingame-lang <代碼>` 與環境變數 `HR_INGAME_LANG` 決定（實驗性，預設空），不進偏好設定檔，F4 只切換前端介面文字。原因：規格 009 完成前每個對白框都是「硬編碼說話者名牌加譯文」，混合語言畫面是否可接受由使用者決定（第 12 節 U4）。決定接受後，再以修訂 `006` 的方式讓 F4 帶動。
- F1 的「遊戲內文字」一行有兩種值：`原版（繁體中文）`，或 `語言包 <代碼>（部分翻譯）`；後者要求語言包通過 manifest 驗證。因為 `LangDir` 在啟動時綁定，沒有「已選待重啟」狀態（偏好設定不記遊戲內語言）。新字串五種語言都要補，字型子集的字元表要重產。
- 發行說明與 F1 標示「部分翻譯：對白與敘述」，不稱「支援某語言」。

### 3.9 洩漏防線

進版控的檔、`docs/re/` 的收據與子代理報告搬運的路徑，一律遵守：

1. 只含 id、計數、雜湊、位址與個別字碼，不含原版文字與含原文的樣張、before/after 對照。樣張、批次報告、對照圖只放 `workplace/`。
2. 清冊的 `note` 欄與詞表禁止含原文，由建置器以下述內容判準檢查。
3. **內容判準（演算法）**：由使用者的原版匯出每個長度 >= 8 bytes 的項目，同時以 Big5 位元組與 UTF-8 解碼文字兩種形式，在掃描範圍的所有檔案中做子字串搜尋。範圍含發行包目錄、`git ls-files` 列出的檔、`docs/`。命中只輸出路徑與 id，不輸出內容。短於 8 bytes 的項目不掃（與一般詞無法區分）。此判準抓不到簡體轉換版與其他語言的譯文，該風險由使用者決定（第 12 節 U1）。
4. `tools/pkg/leakscan.py` 加入內容判準與 `l10n-packs`、`l10n` 路徑判準（路徑規則沿用，內容判準新增）。
5. 負對照的 fixture 在測試執行時由使用者原版產生到暫存目錄，原版缺檔就 skip，**不入版控**。
6. `.gitignore` 已含 `/l10n/` 與 `/l10n-packs/`；決定進版控後才移除前者。若要附進發行包，另設旗標 `HR_WITH_L10N`（比照 `HR_WITH_HD`），版本字串加後綴，附說明檔，只供私人流通；repo 保持 private，轉公開前處理 git 歷史並更新 `LICENSE` 第 2 條。

### 3.10 翻譯流程

- 原文（匯出的 `src_text`）**只送往 Claude Code 子代理**（與主 session 同一服務）。其他服務（codex、外部機器翻譯、第三方譯者）先問使用者（第 12 節 U2；`AGENTS.md` 第 12 節 M8 的先例：外送原版美術被分類器擋下）。
- 翻譯子代理的 prompt 逐項引用 `AGENTS.md` 第 11 節：可寫目錄 `workplace/l10n-work/<代碼>/<批次>/`（批次唯一檔名）、唯讀來源 `workplace/l10n-src/`、禁止修改的目錄（其他 repo、`~/.claude/`、`~/.cache/`、`/home/anr2/cht/dosgolem`）、禁止 commit 與 push、Docker 規則、`hr-*` 前綴、禁止 prune 與 rmi、回報格式。批次流程依 `~/.claude/knowledge-base/workflows/batch-subagent-localization.md`（七步，含全域一致性掃描）。
- L3 閘門含「試作一批給使用者確認風格與尺度」。
- `accepted` 只能在使用者明示接受後，由主代理批次設定，並記錄日期、範圍與接受語句（比照 `AGENTS.md` 第 12 節對 HD 的做法）。定義：機械檢查通過，加獨立回譯審查，加使用者看版面樣張，並標示「未經母語者審閱」。以抽樣加整體接受取代逐條（抽樣比例與最壞案例，即最長行、最多行，寫進閘門）。
- 專有名詞策略（對白內人名地名先譯或先保留）與 `SHOPTAB` 的納入時機（商品名也出現在硬編碼的道具名表，單獨翻譯會與背包畫面不一致）列使用者決定（第 12 節 U4）。

## 6. 失敗模式

| 情形 | 預期 |
|---|---|
| 原版輸入雜湊不符 | 建置失敗，不產生語言包 |
| 清冊 `src_sha256` 與原項目不符 | 建置失敗，點名項目 |
| 譯文違反預算（長度、控制碼、空白、白名單、佔位符、行寬、行數、缺字碼） | 建置失敗，列出全部違規項目的 id |
| 字集超過可用自訂碼數 | 建置失敗，列出超出的字 |
| 譯文含白名單外且沒配到自訂碼的字 | 建置失敗（不得以 `?` 或空白悄悄替換） |
| `accepted` 列的 `acc_sha` 與 `text` 不符 | 視為 `candidate`，建置報告標示 |
| 語言包 manifest 驗證失敗，或缺 `CFONT.15` | 前端不啟用該語言包，記一行，遊戲內文字維持原版 |
| `LangDir` 指向不存在的目錄 | 等同空，記一行 |
| 語言包缺某檔案 | 該檔案回退原版（語言層缺檔規則），建置報告標示 |

| 寫入模式開語言層的檔 | 拒絕（存取被拒），不複製進暫存層 |
| 長跑中語言包造成無進展或例外 | 依 `docs/spec/005` 的診斷分類，並加 (d) 語言包內容類（第 11 節）：同輸入冷啟動，分別用 identity 包與譯文包，比對停機點，不用狀態檔 |

## 7. 玩家垂直路徑與存檔影響

玩家路徑：啟動（帶或不帶 `-ingame-lang`）、新遊戲、對話與選單、商店、存檔與讀檔。語言包只影響顯示：句子層級的檔案類文字不在存檔內，所以存檔位元組不隨語言改變；專有名詞（勢力名等）在存檔內的名稱欄位維持原文，檔案類文字走譯文，**畫面上同一勢力可能兩種寫法**（已知差異）。`FNAME.DAT` 的國名 token 來自段 4073（不翻譯）。存檔與原版互通。收據要求：
- identity 包：同一輸入與步數，`GAMEFILE.00N`、`FNAME.DAT` 與無語言包逐位元組相同。
- 譯文包：因繪製指令數、點擊節奏不同，同輸入同步數到不了同一遊戲狀態，所以不比位元組。改為跨載入：有包存的檔在無包 Session 載入，反之亦然，驗證結構與欄位不變。
- 語言包機器人長跑後，掃描它產生的 `GAMEFILE.00N`，不得出現語言包獨有的位元組序列（例如任何 lead `E0` 至 `F9` 的成對位元組出現在段 4073 範圍），以排除遊戲把顯示文字複製進存檔區。

## 9. 原版 oracle 與已知差異

繁中 identity 語言包的 oracle 是原版（dosgolem 同狀態）。其他語言沒有原版對應物，驗收靠樣張與使用者過目。已知差異：
- **混合語言是必然**：說話者標籤（段 3EA3）、選單、按鈕、人物名、地名、戰鬥紀錄屬硬編碼，每個對白框都是「繁體名牌加譯文」。規格 009 完成前任何語言都如此。L1 試點量測各畫面字元來源比例（`287C:02E1` 的來源字串位址，檔案緩衝對硬編碼區）作為使用者決定 U4 的數字。
- 圖像內文字不翻譯（標題標誌、地圖上烘進圖的國名）。
- 勢力名等專有名詞在存檔內維持原文，畫面上可能兩種寫法。
- `COUNTRY.MES` 項目 5 至 10 在原版少讀第一個雙位元組字（強推論）；含譯文的包重算精確偏移，與原版行為不同（U6）。
- 語言切換需重新啟動前端；F4 不帶動遊戲內語言。
- 同一行內原版字模（硬編碼字串）與補丁字模（譯文）筆畫風格不同。
- 譯文未經母語者審閱（AI 草稿）。
- 英文與韓文的詞距待第 3.6 節實驗，現在不導入。
- 影響範圍是 `MAIN.EXE` 的檔案類文字；`OP.EXE`、`END.EXE` 未查。

## 10. 停止線與權利邊界

- 停止線：譯文或字模涉及未盤查的來源；字集超過可用碼數；需要修改原版 EXE 或把原版位元組放進任何版控或發行包；L5 前想讓 F4 即時換字模；長跑出現語言包造成的新停機點；內容判準在版控或 `docs/` 命中原版項目；原文送往 Claude Code 子代理以外的服務而使用者未答覆。
- 權利：譯文是原版文字的衍生物。預設（第 12 節）：清冊不進版控、不進發行包；語言包只在使用者機器；字模補丁只放 `workplace/`；未決定前不為翻譯畫面建立 `docs/images/` 的新截圖。repo 保持 private。
- 字型來源：只用開放授權字型，授權檔隨補丁保存；不使用原版字型作為其他語言字模的來源，但可以在語言包內整格保留原版字模（建置時從使用者自備的原版取得）。
