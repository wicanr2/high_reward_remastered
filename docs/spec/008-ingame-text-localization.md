## 3. 設計

### 3.1 L0 語言層（dosgolem 通用能力）

- 解析順序改為：暫存層（`Scratch`）、語言層（新增 `DOS.LangDir`）、原版目錄（`Root`）。語言層缺檔時回退原版，語言層本身不可寫（存檔寫暫存層，與現況相同）。其餘規則（只認 basename、大小寫不分、8.3 截斷）沿用。
- `LangDir` 為空時行為與現況完全相同（零成本退路）。`apps/hr/runtime` 的 `Options.LangDir` 傳入；前端由 `-ingame-lang`（預設跟隨 F4 的介面語言，無對應語言包時為空）與資料目錄的 `l10n-packs/<code>/` 決定。
- 切換：每次 `resolve` 讀 `LangDir` 的當前值（原子讀取）。MES 與 ESPMES 逐次開檔，所以換 `LangDir` 後下一次取字就生效，不必重啟 Session。`CFONT.15` 的 handle 常開，換語言不會換字模（L5 的實驗項目，第 4 節）。
- 通用性：位址與檔名都不在 dosgolem 內。判準「換一支 binary 之後這段還成立嗎」成立。

### 3.2 語言包的產生（不散布原版位元組）

- 發行與版控的內容只有譯文清冊與建置工具，不含任何原版檔案或其轉存副本。語言包由使用者機器上的建置步驟，以**使用者自備的原版檔案**加上清冊組出，寫到資料目錄的 `l10n-packs/<code>/`：
  - 每個檔案類檔案（`COUNTRY.MES` 等）：解析原版，逐項以清冊覆蓋譯文，沒有譯文的項目保留原位元組，序列化後寫出。
  - `CFONT.15`：以原版為底，把清冊用到的自訂字碼的字模寫進對應位置（第 3.5 節）。
  - 建置前核對每個原版輸入的 SHA-256，不符即失敗，不猜測套用（`AGENTS.md` 第 2 節）。
  - 清冊每列綁定原項目的雜湊（第 3.3 節）：原版項目與清冊不符時失敗，不覆蓋。
- 語言包是建置產物，路徑在資料目錄，不進版控與發行包（`leakscan` 的判準納入 `l10n-packs`）。

### 3.3 譯文清冊

位置 `l10n/<code>/<檔名>.tsv`（UTF-8，製表符分隔）：

| 欄 | 內容 |
|---|---|
| `id` | `*.MES`：`<檔名>#<項目索引>`；`ESPMES.MRG`：`ESPMES#<群組>.<子>`；`SHOPTAB.TBL`：`SHOPTAB#<記錄>.<欄位>` |
| `src_sha256` | 原項目位元組（去掉結尾 NUL，保留內部 `0A`）的 SHA-256 前 16 碼 |
| `src_bytes` | 原項目位元組數（預算參考，不含原文） |
| `text` | 譯文（UTF-8，`\n` 表示換行，`%` 佔位符原樣保留） |
| `status` | `candidate`、`accepted`、`keep`（保留原版位元組，不翻譯） |
| `note` | 譯者備註（譯名、語境），選填 |

- 清冊**不含原文**。譯者需要原文時，用建置工具從使用者的原版檔案匯出到 `workplace/`（不進版控），格式 `id`、`src_text`（Big5 解碼）。
- 譯名一致性：人名地名等專有名詞另有 `l10n/<code>/glossary.tsv`（`term_id`、`譯名`、`備註`），來源詞以 `src_sha256` 標識，不收原文。批次翻譯流程依 `~/.claude/knowledge-base/workflows/batch-subagent-localization.md`。

### 3.4 預算與檢查（建置工具必須強制，違反即失敗）

| 檢查 | 規則 | 依據 |
|---|---|---|
| 單項長度 | 編碼後位元組數 <= 0x1FF（511） | 020 第 4.1 節（緩衝 0x200，讀取不檢查） |
| 控制碼 | 不含 `0x00`；`0x0A` 只用於換行 | 020 第 7 節 3 |
| 佔位符 | `%` 序列的個數、順序、型別與原項目相同（原版不支援位置參數）。原項目的佔位符序列由建置工具從原版項目解析，不存在清冊 | 020 第 2.3 節；Borland 版不支援 `%n$`：強推論 |
| 名稱欄位 | `SHOPTAB` 欄位 <= 20 bytes，尾端補 `0x20`；其他定寬欄位（若日後納入）同規則 | 020 第 2.2、2.3 節 |
| 行寬 | 每行（以 `0x0A` 或項目結尾分隔）位元組數 <= 該項目的最大位元組寬度，預設 30（保留一格，避免觸發 `1676` 的寬度停止，見 020 第 3.1 節 lead 表問題）。逐項最大寬度（`1676` 呼叫點的第三參數）未普查前，用預設並在建置報告列出所有行寬 > 24 的項目 | 對話框 248 像素 ＝ 31 位元組：confirmed；逐項寬度：未知 |
| 自動折行 | 建置工具對超寬行依單位寬度（半形 1、全形 2 位元組）自動插入 `0x0A`，優先在標點與空白之後折，不拆自訂字碼的雙位元組對 | 設計決定；避開 `1676` 自動折行的未驗證路徑 |
| 空白 | 對話框類項目（走 `237B:01A3`）的譯文不得依賴半形空白（會被略過）；英文的詞間空白用第 3.6 節方案處理，未解決前英文不導入 | 020 第 3.1 節，confirmed |
| 字碼 | 每個字都有字碼（原 Big5 碼或第 3.5 節自訂碼）；trail byte 在 `0x40` 至 `0x7E`、`0xA1` 至 `0xFE`（不會撞到 `%`、`0x20`、`0x0A`） | 020 第 7 節 3 |

### 3.5 字碼配置與字模（L2）

- 原則：**原版用到的 1716 個字保留原碼與原字模**（硬編碼字串與段 4073 仍會畫它們）。譯文的字若是這 1716 字之一，用原 Big5 碼，字形沿用原版字模（繁體字形）。其餘字配自訂碼。
- 自訂碼範圍：lead `0xE0` 至 `0xF9`（`1000:966C` 的表把它們當雙位元組 lead，折行路徑走成對分支，020 第 3.1 節），trail 為上述兩段（每個 lead 157 碼），共 4082 碼，扣掉原版已用字所占碼位。可用碼數在 L2 建置時計算並寫入報告；若某語言的字集超過可用碼數，閘門失敗，不縮字集硬塞。
- 每個語言一份 `CFONT.15`：以原版為底（同大小 416,010 bytes，同公式定位），把自訂碼位置的 30 bytes 換成該語言的字模。簡體、日文、韓文字模來源見第 3.7 節。因為每個語言有自己的 `CFONT.15`，自訂碼可跨語言重用。
- 字模產生：由開放授權的字型（OFL 或公有領域，逐一登記來源與授權）以固定程式光柵化為 15 列 x 16 位元（bit 15 在最左），閾值與位移固定並記錄。光柵化結果是衍生字模，只存在語言包（建置產物），不進版控；版控保存的是來源字型的識別（檔名、SHA-256、版本）與光柵化參數。
- 品質：15x15 光柵化對筆畫多的字可能糊。每種語言導入前，由建置工具產出字模樣張（`workplace/`），使用者過目通過才算（第 4 節閘門）。

### 3.6 英文的特殊問題（L3 英文閘門，現在不導入）

原版半形字模沒有小寫字母與大多數標點（020 第 3.3 節），對話框又略過所有 `0x20`。020 第 4.4 節提出以「雙字母字模」處理：把兩個 8x15 半形字模並排放進一格全形字模，ASCII 可印字元兩兩組合。本規格不採納也不否決，列為待實驗：
- 可用自訂碼只有 4082 減已用，小於 95 x 95 ＝ 9025，所以需先做雙字母頻率統計，只配常用組合，其餘退為單字母加補位字模；或改走 lead `0xA4` 至 `0xDF` 範圍（折行路徑把它們當單位元組，但建置工具已預先折行，行寬 <= 30，不會觸發）。
- 實驗內容與驗收在 L3 英文閘門之前補成獨立 DRAFT 小節，經審查才動手。在此之前，英文不在導入範圍。

### 3.7 字模來源（未決，阻擋 L3）

- 簡體、日文（新字體）、韓文需要 15x15 字模來源。候選必須是可再散布，或可在使用者機器上由開放授權字型光柵化的來源。授權條款是否允許（含 copyleft 條款對衍生字模與語言包的影響）由盤查文件逐一讀授權全文後判定，不憑記憶。
- 在 L3 每個語言開工前，另做來源盤查（`docs/re/` 新增證據文件）：字型名稱、版本、SHA-256、授權全文、涵蓋字集（對照該語言譯文用字）。沒有通過盤查的來源不使用。

### 3.8 F4 與遊戲內語言

- `docs/spec/006` 第 5 節說 F4 現在只切前端介面文字。本規格 READY 且 L1 實作完成後，F4 同時設定 `LangDir`（若該語言有語言包）。無語言包的語言：遊戲內文字維持原版繁體中文，F1 的「遊戲內文字」一行標示。同一提交修訂 `docs/spec/006` 第 5 節與 F1 的狀態列。
- 生效時機：MES 與 ESPMES 在下一次取字時生效（逐次開檔，已畫在畫面上的文字不重畫）。字模（`CFONT.15`）在 L5 驗證前，切換語言後字模不變，所以**語言切換在 L5 之前只在重啟遊戲 Session（或載入存檔後重開）才完整生效**。F1 與切換提示要如實顯示「下次開始遊戲時生效」。

## 4. 階段與閘門

| 階段 | 內容 | 出口條件 |
|---|---|---|
| L0 | dosgolem 語言層 | 單元測試通過（順序、回退、大小寫、8.3、空 `LangDir` 等同現況）；同狀態 A/B：空 `LangDir` 與不帶該選項的 Session，冷啟動 90M 步與取樣狀態檔 10M 步後畫面 PNG 雜湊、CPU 暫存器、記憶體逐位元相同 |
| L1 | 檔案類文字的解析、序列化、預算檢查、清冊匯出 | 對 7 個檔案做「解析再序列化等於原位元組」（SHA-256 相同，含 `COUNTRY.MES` 偏移表的 +2 偏差原樣）；預算檢查的單元測試；繁中 identity 語言包（全部 `keep`）的同狀態 A/B 與 L0 相同 |
| L2 | 字模重組與自訂碼 | `CFONT.15` 重組等於原檔（SHA-256）；合成測試：在自訂碼位置放已知字模，dosgolem 的 `-call-args 198C:05A2` 取到的 `_lseek` 偏移符合公式、`_read` 的 30 bytes 等於放入的字模，畫面該字的像素等於字模點陣 |
| L3 | 逐語言導入（簡體、日文、韓文，英文待第 3.6 節實驗） | 每個語言：字模來源通過盤查；字集不超過可用碼數；譯文清冊全部項目非 `candidate`（`accepted` 或 `keep`）；畫面樣張使用者過目；同狀態收據（第 6 節）；使用者決定譯文的權利處理（第 9 節） |
| L4 | 規格 009：硬編碼字串與段 4073 | 不在本規格 |
| L5 | 執行中換 `CFONT.15` | 實驗：dosgolem handle 重新指向的可行性與副作用（`docs/re` 收據），通過才可讓 F4 在不重啟下完整生效 |

READY 的範圍：本規格升 READY 時只授權 L0 至 L2。L3 每個語言以「來源盤查文件加樣張通過」為前提，在該語言的 `docs/re` 收據中記錄後才實作。

## 5. 失敗模式

| 情形 | 預期 |
|---|---|
| 原版輸入雜湊不符 | 建置失敗，不產生語言包 |
| 清冊 `src_sha256` 與原項目不符 | 建置失敗，點名項目 |
| 譯文違反預算（長度、控制碼、佔位符、行寬、缺字碼） | 建置失敗，列出全部違規項目 |
| 字集超過可用自訂碼數 | 建置失敗，列出超出的字 |
| 語言包缺某檔案 | 該檔案回退原版（語言層缺檔規則），建置報告標示 |
| 語言包存在但 `CFONT.15` 缺或字模不符 | 前端不啟用該語言包，記一行，遊戲內文字維持原版 |
| `LangDir` 指向不存在的目錄 | 等同空，記一行 |
| 譯文含原版 Big5 字模沒有、也沒配到自訂碼的字 | 建置失敗（不得以 `?` 或空白悄悄替換） |
| 長跑中語言包造成無進展或例外 | 依 `docs/spec/005` 的診斷分類，先判斷是缺服務、原版缺陷或語言包內容 |

## 6. 玩家垂直路徑與存檔影響

玩家路徑：啟動（帶或不帶語言包）、新遊戲、對話與選單、商店、存檔與讀檔、F4 切換語言。語言包只影響顯示：檔案類文字不在存檔內（020 第 4.2 節，命中 0 筆），所以存檔位元組不隨語言改變；`FNAME.DAT` 的國名 token 來自段 4073（不翻譯）。存檔與原版互通。收據要求（同狀態 A/B）：
- 同一輸入與步數，有語言包與無語言包的 `GAMEFILE.00N`、`FNAME.DAT` 位元組相同（排除因畫面文字不同而改變的輸入時序，以固定步數的存檔動作驗證）。
- 讀入原版存檔後行為與無語言包相同。

## 8. 原版 oracle 與已知差異

繁中 identity 語言包的 oracle 是原版（dosgolem 同狀態）。其他語言沒有原版對應物，驗收靠樣張與使用者過目。已知差異：
- `COUNTRY.MES` 項目 5 至 10 在原版會少讀第一個雙位元組字（強推論）。譯文重組時偏移一致，譯文會顯示完整，與原版行為不同。
- 硬編碼字串與段 4073 的名稱在規格 009 完成前仍是繁體中文，畫面會出現混合語言。
- 英文的完整導入待第 3.6 節。
- `CFONT.15` 在 L5 前不隨 F4 即時換。
- 譯文未經母語者審閱（AI 草稿）。
- 逐項最大行寬未普查，用預設 30 位元組與建置報告的長行清單作為保守處理。

## 9. 停止線與權利邊界

- 停止線：譯文或字模涉及未盤查的來源；字集超過可用碼數；需要修改原版 EXE 或把原版位元組放進任何版控或發行包；L5 前想讓 F4 即時換字模；長跑出現語言包造成的新停機點。
- 權利：譯文是原版文字的衍生物。**待使用者決定**：清冊（`l10n/`）是否進版控（private repo，比照 HD 素材）、發行包是否附語言包建置工具與清冊、是否由第三方譯者參與。決定前清冊只放 `workplace/`，不提交。
- 語言包（含 `CFONT.15` 衍生字模）只存在使用者機器的資料目錄，不進版控與發行包。
- 字型來源：只用開放授權的字型，授權檔隨建置工具保存；不使用原版字型（`CFONT.15`）作為其他語言的字模來源，但可以保留原版字模於語言包內（建置時從使用者自備的原版取得）。
