# 002 堆疊大小：在記憶體內改寫 `_stklen`

狀態：DRAFT 第二版（2026-10-03）。第一版經獨立審查（唯讀子代理）有 4 項阻擋，已依據修訂；第二輪審查通過後才標 READY，READY 之前不寫正式實作。
日期：2026-10-03
前置：`docs/re/011-longrun-stack-overflow.md`（證據）、`docs/re/007-fbov-overlay-structure.md`（映像結構）、`AGENTS.md` 第 5、6、7 節。
實作位置：`workplace/dosgolem` 本地分支 `hr` 的 `apps/hr`（執行層補丁，不修改原版檔案）。

## 1. 範圍與排除

範圍：`MAIN.EXE`（SHA-256 `08ed144e8f8d6e97d19f0759bce2420665998143f2f0f056ab7adc718e550e3e`）的堆疊容量。
排除：`OP.EXE`、`END.EXE`、`PSH.EXE`、`SIG.COM`（沒有證據顯示同類問題，也沒有長跑收據）；音效路徑與 EMS（`docs/re/010`）；選單以巢狀呼叫實作這件事本身（遊戲結構，不改）。

## 2. 問題與停機分類

`MAIN.EXE` 的堆疊只有 4096 bytes（`SP` 起點 `0x1010`）。選單與畫面以巢狀呼叫實作，在固定輸入下最深用到 5266 bytes。`SP` 減過 0 繞到 `FFxx` 之後，堆疊落在一個圖形緩衝區上，函式返回取到像素資料，`retf` 跳進視訊記憶體位址範圍（`docs/re/011` 第 4 節）。

依 `AGENTS.md` 第 6 節分類：

| 類別 | 判定 |
|---|---|
| (a) dosgolem 缺服務或實作錯誤 | 否。溢位本身由遊戲程式碼與輸入決定：堆疊深度（頂端 `−` SP）在原版與修補版逐事件相同（`docs/re/011` 第 5.1 節），不依賴模擬器的服務 |
| (b) 原版在別的模擬器同樣當機 | 未驗證，沒有 DOSBox-X 對照。溢位本身（`SP` 繞過 0）與模擬器無關；繞回後是否當機，取決於 `54C0:FFxx` 的實際記憶體內容，在真實 DOS 未量測 |
| (c) 其他：原版缺陷（堆疊容量不足） | 本規格採用此分類，附帶限制：結論限於 dosgolem 內的行為 |

## 3. 決定

遊戲啟動前，在記憶體內把 Borland 啟動碼讀的 `_stklen` 從 `0x1000` 改成 `0x8000`。

| 項目 | 內容 |
|---|---|
| 改寫位置 | 載入後的線性位址 `0x544FC`，即 DGROUP `540F:040C`；原版檔案位移 `0x57DFC`（標頭 `0x4A00` bytes，載入基底線性 `0x1100`） |
| 原值 | `00 10`（`0x1000`，u16 小端） |
| 新值 | `00 80`（`0x8000`） |
| 讀寫者（IDA xref，審查實測） | 只有啟動碼三處碰這個位址：`1000:0062` 讀、`1000:0070` 與 `1000:00A9` 寫。其餘以 `040C` 為位移的指令是 `cs:` 前綴（`2F36`、`33AD`）或 overlay 私有的 `DS ＝ 5BF4`（`7718:2CAA`），不是同一個位址 |
| 啟動碼語意 | `1000:0062` 讀值；小於 `0x200` 補到 `0x200`；轉成段落數加 1；`AH=4Ah` 把程式區塊調整到 `SS` 之後該長度（`1000:0096`）；`SP ＝ 值 ＋ 0x10`（`1000:009E` 至 `00A1`）；`1000:00A9` 把 `SP` 起點存回 `DGROUP:040C` |
| 結果 | `SS ＝ 54C0` 不變，`SP` 起點由 `0x1010` 變 `0x8010`；程式區塊末端由 `55C1` 變 `5CC1` 段落 |

數值依據：觀察到的最大堆疊深度 5266 bytes（一組輸入）、擴大驗證最大 3094 bytes（五組輸入，`docs/re/011` 第 6 節）。`0x8000` 是最大觀察值的 6.2 倍。不保證更深的路徑不存在（第 8 節）。

## 4. 契約

1. 只對 SHA-256 為上述值的 `MAIN.EXE` 啟用。其他映像不改。
2. 改寫前先讀該位址的 u16。不等於 `0x1000` 就拒絕啟動，回報位址與實際值，不降級、不靜默略過。
3. 只在新遊戲（尚未執行任何指令）改寫。載入狀態檔時不改寫：狀態檔已含啟動後的 `SS:SP` 與配置狀態，記憶體內 `DGROUP:040C` 是啟動碼存回的 `SP` 起點（`0x1010` 或 `0x8010`），不是設定值。狀態檔不綁定補丁值：原版堆疊產生的狀態檔（`SP` 起點 `0x1010`）可以載入，但載入後的堆疊仍是 4 KB；執行器載入狀態檔時依 `SS:SP` 起點與記憶體內的 `_stklen` 比對，不一致就在紀錄寫警告。
4. 不修改 `MAIN.EXE`、不寫任何原版檔案。補丁是一個位址、一個 u16。
5. 不改任何遊戲邏輯、座標、資料表與呼叫序。

## 5. 影響面

| 項目 | 預期 | 驗證 |
|---|---|---|
| 程式區塊加大 `0x7000` bytes | dosgolem 1 MB 位址空間內 overlay 緩衝區與遠堆積整體上移 `0x700` 段落（`freeSeg` 由 `7C41` 變 `8341`；overlay 段 `5D2C` 變 `642C`） | `docs/re/011` 第 5.1 節 |
| 存檔 | 存檔內容與堆疊大小無關 | 第 6 節的存檔比對：`GAMEFILE.000` 與 `FNAME.DAT` 逐位元相同 |
| 狀態檔 | 補丁前後的狀態檔不互通（`SP` 起點與配置不同） | 第 4 節第 3 條 |
| 真實 DOS | 常駐記憶體多 28 KB，原版在 640 KB 內的餘量未量測 | 未知，第 8 節 |

## 6. 驗收（同狀態比對）

固定輸入來源（種子、存檔槽、腳本）使兩邊輸入序列相同。因為程式區塊大小改變，記憶體不能逐位元比對，改以下列可觀察與可序列化的內容：

| 對照 | 設定 | 預期 | 已有收據（`docs/re/011`） |
|---|---|---|---|
| 對照組：原版堆疊 | 種子 22、存檔槽 2，`-stklen 0 -no-overflow-stop` | 第 3,093,737,047 步跳進 `A39A:006A` | 第 5.1 節 |
| 偵測器 | 同上，`-stklen 0`（預設偵測） | 第 3,093,473,639 步報堆疊溢位 | 第 5 節 |
| 偵測器正對照 | `-stklen 1024` | 溢位偵測會響：第 276,898,405 步 | 第 5.1 節 |
| 實驗組 | 同上，`-stklen 32768` | 45 億步無停機 | 第 5 節 |
| 事件序列 | `-sp-log` 逐事件比對：步數、輸入、呼叫鏈（overlay 段位址只留偏移）、堆疊深度 | 三對（種子 22 槽 2、種子 40 槽 0、種子 43 槽 3）各 900、713、713 列逐列相同 | 第 5.1 節 |
| 畫面 | 每 2.5 億步畫面索引色雜湊 | 停機前 11 筆相同 | 第 5.1 節 |
| 存檔內容 | 讀槽 0、存入槽 0，比對暫存層檔案 | 兩邊逐位元相同 | 第 5.1 節 |
| 擴大驗證 | 五個存檔槽、五個種子、`-stklen 32768`、80 億步 | 無溢位、無跳出記憶體範圍；最低 SP 餘量大於 `0x4000` | 第 6 節 |

不對照：調色盤雜湊、溢位之後的狀態。偵測器的版本與旗標：`hrsoak`（`workplace/dosgolem` 分支 `hr`，commit `14c13a9` 之後的工作樹，commit 在實作時固定）。

## 7. 推論等級

| 結論 | 等級 |
|---|---|
| 位址、位元組、啟動碼語意、xref | confirmed |
| 原版在該組輸入下 `SP` 繞過 0、之後跳進視訊記憶體 | confirmed（同種子重跑逐位元相同） |
| 堆疊與圖形緩衝區重疊的機制（`ES:DI ＝ 6497:...` 與 `54C0:FFF2`） | 強推論（寫入長度未逐位元核對；DI ＝ 028A 與 `0x282` 至 `0x28F` 的對應見審查紀錄） |
| 修補不改變遊戲行為 | 限於第 6 節列出的對照項目與輸入 |
| 真實 DOS 上也會當機 | 未知 |

## 8. 玩家垂直路徑與未解

- 玩家垂直路徑：目前只有隨機輸入的路徑（存檔槽 2、種子 22：進入選單、子選單、再操作載入圖形的函式，約在第 3.05 至 3.09 億的輸入序列內）。玩家實際會不會走到相同深度，沒有證據。最小重現腳本（人可照做的點擊序列）未做。
- 使用者描述的當機是「進入遊戲後長時間跑才會知道」，症狀（凍結、花屏、回到 DOS、重開）未知，不能確認與本規格是同一個當機。
- 堆疊段上方 `54C0:FFxx` 在真實 DOS 是什麼，沒量測。
- 更深的路徑：隨機輸入與介面探索（`docs/re/012`）沒有走過戰鬥與全部商店畫面。`0x8000` 的餘量在驗證範圍之外沒有保證。執行器要在紀錄寫出本次遊玩的最低 SP，並在 SP 低於 `0x4000` 時警告。
- 沒有 DOSBox-X 對照。

## 9. 失敗模式

| 失敗 | 行為 |
|---|---|
| 位址上的原值不是 `0x1000`（映像或載入位置與假設不同） | 拒絕啟動 |
| 映像雜湊不符 | 不套用補丁；執行器依 `docs/spec/003` 第 2 節拒絕啟動 |
| 載入狀態檔且堆疊與補丁設定不一致 | 警告，照原狀態執行 |
| 補丁後仍溢位（超過 `0x8000`） | 執行器報堆疊溢位並停機，存現場，不繼續執行 |

## 10. 實作要求

- 補丁寫成 `apps/hr` 內的一個函式（輸入機器與映像雜湊，輸出是否套用與原值），附單元測試：原版缺檔就 skip（不用替代檔）；原值不符回錯誤；雜湊不符不改。
- 長跑驅動、探索器與正式執行器共用這個函式，`hrsoak` 現有的內嵌版本移除。
- 執行器啟動時在紀錄寫一行：補丁名稱、位址、原值、新值。
- 權利邊界：補丁描述只含位址、位元組與數值，不含原版內容；執行時才在記憶體內套用。
