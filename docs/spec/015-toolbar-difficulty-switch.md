# 015 工具列立即切換難度

狀態：CONFORMED。日期：2026-11-03。來源與目前狀態入口：[037](../re/037-difficulty-modes.md)。

## 使用者決定與範圍

使用者要求在工具列設定難度，並選擇「立即切換」。視窗上方增加難度選單；選另一模式後，先提醒儲存，確認才回到所選模式的標題。原版與高難度進度依 [014](014-difficulty-modes.md) 分開，不轉換目前遊戲的能力、債務或存檔。開場選擇頁與直接啟動旗標保留。

本項只改前端的工具列、執行生命週期及輸入座標。014 的倍率、指定商店、31,839-byte 存檔、來源驗證及語言層允許清單維持原契約。不擴大為自動存檔、遊戲中換算規則、新封包或 Release。

## 固定輸入與已證實的程式事實

- 基準 fork 為 `d7aae8e52b75a99c438fc308374e75d9a245f80c`，Go 1.26.7／Ebiten 2.9.9，工具鏈 `hr-go-ebiten:1.26.7-2.9.9-r1`。MAIN.EXE SHA-256 沿用 `08ed144e8f8d6e97d19f0759bce2420665998143f2f0f056ab7adc718e550e3e`。
- 已證實，原始碼：`apps/hr/play/main.go` 的 `start` 在 `hrrt.Open` 成功後才建立音訊、偏好寫入者、HD 合成及 Run goroutine；`td.run` 已集中處理結束。新模式可先驗證／開啟，失敗時保留舊遊戲。
- 已證實，原始碼：`apps/hr/runtime/session.go:629` 的 `Run(ctx)` 在取消時返回 nil，可在前次 goroutine 完全結束後對同一 Session 重開；Run 開始會重設牆鐘／ticks 基準，不補跑暫停時間。`HoldAdapt` 只抑制降頻，不暫停 CPU，不能拿它當選單暫停。
- 已證實，原始碼：`game.go` 的邏輯遊戲區是 1280×800，滑鼠轉換為 x/2、y/2；`switcher.Quit` 只要求取消預載，尚未等候工作結束。重建 Session 前須收完預載，避免舊工作釋放新模式共用的素材。
- 已證實，原始碼：`session.go:419..434` 的一般滑鼠放開會等三次輪詢；`prefsWriter.Close` 及 `audioOut.close` 的一秒等待是行程退出政策。工具列不能把它們當成切換屏障。`internal/dos/dos.go:875` 有可在停止後關閉檔案的 Close。
- 位址空間為 Go 原始檔與行號，沒有新增 DOS 記憶體掛鉤。配置原型為本機 `workplace/out/difficulty-toolbar-prototype.png`，不作已實作證據。

## 工具列與輸入

- 遊戲畫布維持 1280×800，上方增加 44 像素工具列；預設邏輯視窗為 1280×844。一般視窗依倍率增加高度，遊戲畫布不重排。全螢幕及任意視窗大小由 Ebiten 等比縮放。
- 左上顯示「難度：目前模式」，選單提供原版／高難度，現用模式有標記。使用現行深色面板與 Noto，五語文字須量測及檢查字形；箭頭與標記用向量，不依賴特殊符號字模。
- 初始選擇頁仍在原座標繪製，新增的高度留白。`-no-toolbar` 保留舊 1280×800 畫布及輸入座標，供既有錄影／驗證工具相容；一般玩家預設有工具列。
- 遊戲中的滑鼠先減去工具列高度，再走既有 x/2、y/2。工具列、下拉選單、確認視窗與被消耗的外部點擊都不能穿透 DOS。
- 滑鼠進入工具列時，若有前端持有的按鈕，先暫停並 join Run，再由受控入口清除 Session 的 held／relPending／pollsAt、尚未處理的滑鼠 inbox 及 DOS 按鈕／按放計數，不依賴三次 CPU 輪詢。保留鍵盤、滑鼠位置／範圍／觀測紀錄，以及無關的 CPU／記憶體／進度。開選單同樣先做此清除，恢復後不把同一按下／放開補送進遊戲。清除入口只能在 Run／RunSteps 都已停止時呼叫。
- 工具列／選單使用系統游標，遊戲區使用既有遊戲游標。
- F1～F4、F11、F12 與視窗縮放的遊戲內座標保持原樣。F12 保存遊戲畫布，不包含工具列。模態選單期間只處理選單操作、Esc 與 Ctrl+Q；不把鍵盤輸入送進遊戲。

## 切換狀態與失敗模式

1. 開啟工具列選單：取消本輪 Run context，等 goroutine 結束後才顯示選單，保留同一 Session 的 CPU／DOS／記憶體。背景 HD 合成只讀已發佈畫面。關選單時可恢復同一 Session，不重新載入存檔，也不補跑停留期間。
2. 選目前模式：收起選單、恢復遊戲，沒有重建或寫入。
3. 選另一模式：顯示目標模式、提醒先儲存、未存進度將不保留。預設焦點為取消；Esc、取消按鈕或預設 Enter 均恢復原遊戲。方向鍵／Tab 可選確認，滑鼠也可確認。確認前不建立目標 profile。
4. 確認後：先準備目標語言及 hrrt.Open，取得尚未 Run、尚未開啟新輸出 worker 的候選 Session。失敗時記錄詳細日誌，顯示切換錯誤；舊模式、Session 與未存進度仍在，關閉錯誤後恢復。不能退到其他難度或清除資料。
5. 準備成功後：取消並 join 舊 HD 預載、釋放其 HoldAdapt、結束 HD view、關閉且 join 舊 Run、關閉舊 DOS 檔案，再啟用候選 Session。每輪遊戲資源收尾須可重複呼叫，不能重啟已結束的 runner。
6. 偏好寫入者與音訊輸出改為應用程式級，各只有一份，不在難度切換時 close／重建。新模式沿用同一序列化 writer，延後完成的舊寫入不能跨 writer 覆蓋新偏好。音訊透過既有 pullSource 的互斥鎖綁定新 Engine；綁定返回後，所有有效拉取者都只讀新 Engine，不能新舊引擎同時推進。裝置開啟、停滯接手與行程退出逾時沿用原契約，不增加每次切換的裝置關閉工作。程式最後退出才關閉共用資源，close 須冪等。
7. 新模式從標題開始，使用該模式的 SaveDir。選取模式及目前文字只有在成功後更新；不自動讀任一槽，也不把難度寫成略過開場選擇的偏好。
8. 主題、介面語言、靜音與明示的遊戲內語言覆蓋保留；沒有覆蓋時，重啟模式依目前介面語言準備遊戲文字。stLoading 的目標尚未套用，不取代目前主題；stApplying 已完成素材綁定，採 Current 主題重啟，即使舊 Display 尚在等候發佈。

## 驗證與停止線

- 有界 runner：暫停返回後沒有 CPU 進展；反覆暫停／恢復仍是同一 Session；結束不再恢復，沒有重複 Run 或取消造成的假停機。測試須等待實際 goroutine 結束。
- 按下後未滿三次輪詢就開選單，再取消恢復；檢查真正 DOS Buttons、按放計數、Session inbox 及 held，不只看前端事件。清除前後的 CPU／遊戲記憶體相同。
- 受控延後的單一偏好 writer、預載 worker 與音訊 Read：新偏好序列保持正確，舊預載必須 join，Engine 綁定等待舊 Read 完成，綁定後舊引擎不再前進。每輪資源及應用程式 close 重複呼叫不重建或重關。
- 工具列邊界／縮放、原本遊戲輸入、按鈕釋放、取消／同模式無重建、預設取消、目標啟動失敗保留舊 Session、連續雙向切換及資源等候。
- 五語文字與字形邊界，既有前端測試、受影響的執行層回歸及 Windows 編譯。
- Linux 實際視窗：正常新遊戲，在原版與高難度間雙向切換，分別確認 1000 萬／5000 萬、模式標題、可取消與五槽進度各自載入。不得用 raw state 或注入金錢取代此路徑。
- 測試 profile 只使用本輪目錄與未修改的既有正常存檔副本；玩家正式進度及原始來源唯讀。新硬體／原版規則無變更，不重開劇情全通關或已結束的額外 parity 抽驗。
- 原版 oracle 為既有 dosgolem 的 014 收據；本項比較新增工具列外的遊戲畫布及存檔狀態，不宣稱原版 DOS 有這個工具列。Windows／macOS 原生操作仍為限制。
