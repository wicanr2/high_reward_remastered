## 回饋分析與原版事實

回饋指出三個互相關聯的問題：載具讓攻城缺少代價，取得強力載具過早讓路線失去成長節奏，巨額收入讓償債目標太早失去吸引力。只增加債務與削減收入，可能增加重複賺錢的時間，仍然保留無傷攻城。設計重點是取得時機、攻城代價與敵人配置，再用經濟限制維持目標。

| 項目 | 證據等級與目前結果 |
|---|---|
| 初始債務 | 已證實，限本專案固定輸入及正常新遊戲：原版為 10,000,000，高難度為 50,000,000。回饋中的「100 萬負債」與此不同，不能直接當作調整基數。定位及收據見 [037 的債務與金錢](../re/037-difficulty-modes.md#債務與金錢)。 |

### 載具的兩種策略

飛機與戰車各有一個強度選單，可混搭，例如飛機「運輸為主」、戰車「保留後期作戰價值」。母開關關閉時使用原版能力，強度選擇不生效。

| 策略 | 飛機 | 戰車 |
|---|---|---|
| 保留後期作戰價值，預設 | 降低攻擊與耐久，仍可參與後期戰鬥。有防空的城市應帶來實際代價；需要同條件攻城收據證明，不能只調顯示數字。 | 降低攻城收益，保留移動及運兵優點。大炮應有值得投入的火力用途，戰車仍可作為後期選擇。 |
| 運輸為主 | 更大幅降低攻擊與耐久，主要提供飛行與運送用途，不作為廉價攻城主力。 | 更大幅降低攻擊，主要保留移動與運兵用途，攻城火力以其他兵種補足。 |

使用者確認第一輪候選：均衡飛機攻擊 50%、最大耐久 75%；運輸飛機攻擊 10%、最大耐久 25%。均衡戰車攻擊 50%、運輸戰車攻擊 10%，兩者最大耐久維持原值。敵我同型載具一併套用，大炮不改，載具防禦與移動、價格、運送及起降規則維持原版。正整數向下取整且至少 1，原值 0 維持 0，不重複累乘。

## 選項交互作用

- 同一場劇情戰鬥只套用一次劇情階段規則。若發生於西路，不再因地區重複乘相同的敵軍能力倍率。城市配置可以影響敵軍組成，但不能默默突破已確認兵種及數量範圍。
- 特殊寶藏若已屬現行 13 組之一，加入分類後仍只減半一次。若原版分別呼叫通知與入帳，各處理一次自己的引數，不在最終現金再扣一次。
- 飛機商店限制只影響販售；不等於刪除敵方飛機、收回存檔中的飛機或禁止玩家使用既有載具。
- 降低飛機耐久若不會增加攻城損耗，便無法單獨解決回饋的無傷攻城。防空與反擊作用須獨立驗證；沒有證據時不補造命中公式。
- 載具調整與城市守備一起測試。若重要城市有裝甲但 AI 不會使用，或防空不參與攻城反擊，不能以資料表有單位就宣稱平衡問題已解決。
- 所有開關關閉代表使用原版規則的自訂挑戰，仍不得與正式原版進度混用。這項隔離沿用使用者確認的每組設定獨立進度，由 017 管理，不變更 014 的舊目錄契約。

## 操作原型與進度設計

設計原型位於 `workplace/out/difficulty-options-prototype.html`，畫面為同根的 `.png`；來源及選項資料為 `.py`、`.json`。正式前端已使用既有深色面板及 Noto 接入八項設定、兩種載具策略與恢復預設；原型保持獨立，不讀寫遊戲或存檔。

由工具列進入設定，保留原版／高難度入口。設定頁顯示八項及目前挑戰規則；取消回原 Session。變更規則沿用 015 的先儲存、確認後回標題，不在目前戰鬥中換算能力。相同有效設定只收起視窗、不重建。

使用者已選擇每組完整設定各自保存，切回同組即可續玩。進度綁定具版本的規則快照，避免先用低債務開局再切換，或反覆切換累乘能力。舊 `hard-v1` 維持 014 規則，新規則不自動套入既有存檔。具體設定與共用投影契約由 [017](017-custom-difficulty-profiles.md) 審查，原版 31,839-byte 存檔不改寫。

4. 檢查組合：單項關閉不關閉其他規則，通知與入帳一致，重入及讀檔不重複施加，原版輸入與舊進度不變。未指定設定與明確關閉要可區分，不能用零值意外開啟規則。

平衡驗收目標是保留早期成長、後期載具用途及攻城代價；不是把所有數字提高或確保玩家必須刷到特定兵種。玩家回饋及實際試玩仍是取捨依據，未實測前不宣稱平衡完成。

## 第一輪接線契約

### 輸入、版本與模式

輸入及位址空間沿 038，設定及進度沿已 CONFORMED 的 017，基準 fork 為 `5c6cd647f38e1e999f45e767bcac6244b575293f`。自訂規則 revision 為 `challenge-v1`。任何數值、階段或地區政策後續改版必須更換 revision，不無聲改寫既有挑戰。

新增模式 `custom` 及 `Options.ChallengeRules`。零值仍為原版，舊 `hard` 仍執行 014 固定規則。`custom` 未明示設定時採八項全開及 balanced；明示設定必須驗證並複製，不保留呼叫端可變指標。其他模式若帶自訂設定應回錯，不能悄悄忽略。

`Open` 仍先驗完整合法原版，custom 才由 017 取得共用 DataDir 與獨立 SaveDir。語言包從未修改的來源準備；custom 沿 014 的八檔資料允許清單，拒絕語言層進度污染。Scratch 一直是該完整設定的 profile，不能回退其他設定或原版附帶進度。

### 啟動時的資料變更

在首次 CPU 指令前，只修改已驗證 MZ 的執行記憶體。來源、共用投影及語言資料不改。先收集所有變更，核對來源／欄位與範圍後才寫入；失敗不執行 CPU。

- 債務：開啟時依 014 改 1000 萬為 5000 萬；關閉不改。不在讀檔後再乘。
- 載具：依上方八型記錄及選定策略改攻擊與飛機最大耐久。它們位於原版保存區之外，每個 Session 只初始化一次。當前耐久仍由正常購買、維修、損耗及存檔處理，不在每幀壓縮或補滿。
- 西路守備：只對 region 6／7／8／9／10 的一般城市、首都及要塞處理，排除洞穴等其他類型及私人住所 town 64。`+1Ah/+20h/+22h` 分別是城防／反擊火力／防護。region 6／7 為 `125/125/115%`；region 8 為 `150/150/125%`；region 9／10 為 `175/175/150%`。正值向下取整、至少 1，封頂 999。初始 region 4 不處理。這些欄位在保存區內，載入已屬相同規則的正常存檔後不重套。
- 城市載具：首都／要塞類型 0／1，排除 region 4 及 town 64，共 36 座，完整名單在 038 的本機證據。region 5／6／7 最低型號索引 1，region 2／3／8 最低 2，region 0／1／9／10 最低 3。`FF` 視為缺少，補到該最低型號；原本較高索引保留。只改 `+24h` 飛機與 `+25h` 戰車，不動炮種、所有權、城型、道路或獨立駐軍 ID。這些也是保存區欄位，不在讀檔後重套。

執行記憶體與 IDA 原始位址的換算沿 007／038 的固定 MZ 載入，表指標及欄位須核對固定輸入。載具索引限 0 至 7 或 `FF`，城防欄位限原版 0 至 999，城鎮限 0 至 98，國家限 0 至 10；不符即回錯。不得依檔名或單一命名跳過完整來源檢查。

### 前端與相容入口

- 開場仍為兩張卡，原版取得預設焦點；高難度卡啟動 custom 的目前待選設定，初值八項全開。設定入口可在開場及工具列使用。
- 舊 hard 可由工具列「舊高難度」或原有 `-difficulty hard` 啟動，繼續既有 `saves-hard`。新 CLI 為 `-difficulty custom`；`-challenge-rules <JSON>` 僅在明示 custom 時接受，解碼失敗不建立 Session。既有錄影工具使用 original／hard 時語意不變。
- 工具列顯示目前模式，提供原版、新高難度、舊高難度及設定入口。不能以相同 Difficulty 字串就判定兩組 custom 是同一設定，必須比較 017 摘要。
