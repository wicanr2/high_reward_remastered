# 013 城市編成畫面的隊長姓名修正

狀態：CONFORMED。日期：2026-10-14。範圍限城市編成的隊長姓名修正。證據與同狀態收據：[036](../re/036-formation-commander-names.md)。使用者已要求修正原版姓名錯位。規格與實作唯讀審查無阻擋，收據 `workplace/out/review-troop-names-spec.md`、`review-troop-names-implementation.md`。

## 範圍與輸入

只修正城市「部隊間編成」的隊長姓名來源。一般士兵、人物能力、裝備、圖像、部隊配置、遊戲規則及存檔格式沿用原版。原版 EXE 不改檔、不散布。

固定 `MAIN.EXE` SHA-256 `08ed144e8f8d6e97d19f0759bce2420665998143f2f0f056ab7adc718e550e3e`。既有 `runtime.Open` 拒絕其他版本。工具為 Go 1.26.7、IDA Pro 9.4；位址基準與推論等級見 036。

## 修正契約

- 遊戲專屬修正放 `apps/hr/runtime`，不進 dosgolem 通用 CPU 或 DOS 層。
- 在原版執行 IDA `80F0:1917`，`imul ax,2Eh` 前，只將 AX 的姓名索引 `2→4、3→2、4→3`。其餘索引不動。
- 僅當所選士兵槽為 0、所選部隊編號在 `0..5`、部隊記錄首位士兵類型等於 AX，且型別為 2、3、4 時套用。局部部隊指標須與全域部隊基底加 `編號 × 0x17E` 相符。
- 識別 overlay 384：載入段前一段落 `+0x0E` 必須為 stub `53E3`，該 stub 的 `+0x10` 必須反指目前 CS。不能把某次執行的 `600A` 當固定段。
- 比對 `80F0:1913..1929` 的完整指令簽章：`26 8B 47 55 6B C0 2E 05 08 00 68 49 39 50 1E 68 01 01 16 8D 86 D0 FE`，其中 `3949` 為已重定位的原版姓名資料段。簽章、指標、範圍或槽位不符就不改 AX。
- 不改原版資料表、DOS 記憶體、指令位元組、存檔或一般人物類型。只改這次繪製姓名時的暫存器輸入。下一個能力值格式化會重新讀取原始部隊記錄。
- 修正預設啟用，所有主題與語言共用。譯文沿用修正後的原始姓名匹配，無新增譯文表。保留可關閉本修正的診斷選項供原版 A/B，正式預設不關閉。

## 驗證與停止線

1. 負對照：修正前正常新遊戲、城市選單、六位隊長的點選，2、3、4 的名字須確實錯位。
2. 同狀態比較：同一原版快照與輸入，開關修正，各隊長名稱符合正確順序；能力值、裝備、圖像與部隊記錄不變。一般商人、砲兵、舞孃仍正確。
3. 邊界測試：錯誤 overlay、錯誤簽章、未載入／已重用段、非隊長槽、非法部隊編號、異常指標、類型不符不改暫存器或記憶體。overlay 換載入位置仍可辨識。
4. 正常玩家路徑：用正式 Session 執行迴圈重新從新遊戲走城市編成，確認修正接線。前端編譯與必要既有回歸通過。
5. 不把修正後姓名稱為原版逐像素相同。這是使用者授權的原版顯示缺陷修正。既有封包、版號、tag 與 Release 不動；本輪不擴大其他玩家路徑或平台實機驗收。

原始收據只留本機。九項原版 A/B、拒絕條件、正常冷啟動、Linux 實際前端畫面、既有冷啟動收據及編譯通過。補丁入口 [0046](../../engine/patches/0046-formation-commander-names.patch)。
