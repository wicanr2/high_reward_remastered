# 010：獨立滑鼠呈現

狀態：CONFORMED。2026-10-08。依據 [033](../re/033-cursor-presentation.md)，修正 Linux AppImage 游標閃爍與移動跳格。範圍包含原版、HD、AI theme；沒有 HD 掛鉤時亦可工作。完成範圍限於下列收據，不含使用者桌面的實機延遲測量。

## 契約

1. 執行層增加預設關閉的呈現選項；只有前端啟用。原版雜湊核對沿用 Open 的完整 MAIN.EXE 驗證。原版座標、指令、記憶體、VRAM、時鐘、输入事件及存檔保持不變。
2. `Frame.Px` 仍是原始 VRAM 快照，診斷與 oracle 保持原義。另附不可變游標資訊、清除游標的呈現像素與「重畫中」狀態，皆由機器擁有執行緒製作。
3. 只接受 40×32、五平面、805 bytes 的原版游標。DS `3E50:02A9` 供前端繪圖，`1BD1` 供當輪遮罩；背景使用 DS `001D` 的 648 bytes。全部尺寸、座標、界限先核對。透明值 16。
4. 旗標 0019/001B 有任一非零時，不把不完整游標當作可直接發布的底圖。已知有效格式的完整游標須背景標頭為 5×32、裁切精靈全部可見不透明像素與 VRAM 相同且至少一個不透明像素。背景位置只取保存標頭，不用最新輸入座標推算。背景還原僅寫呈現副本的游標不透明像素，裁切在 640×400 遊戲區。已知格式但 VRAM 比對失敗標示重畫中，前端最多保留上一張完整底圖 500 毫秒。持續失敗超過期限時回退原版底圖並關閉前端游標；下次有效快照可恢復獨立呈現。開機尚無有效精靈或精靈尺寸／格式不支援時顯示原始畫面，不猜測游標形狀，不進入無限等待。
5. 两旗標皆零時發布原始底圖，前端不繪製游標。HD 合成在有效獨立游標模式及隱藏分支都忽略 `hd.CursorSite` 戳記，使用同一份呈現底圖；重畫中不發布新合成畫面。回退原版分支維持原始戳記與像素，不疊加前端游標。
6. 前端使用已上傳底圖的游標資訊與調色盤。每次 Draw 以目前視窗滑鼠座標定位，遊戲座標換算與输入一致，無 8 像素對齊。限制範圍取該快照的 DOS Mouse Min/Max；Max=0 沿用驅動未限制的語意，VGA Y 轉遊戲 Y 減 40。熱點相減後位置下限為 0，畫面邊緣由裁切處理。視窗外不画游標。
7. 保留原版圖形，於遊戲與文字、說明疊層後繪製，所有 theme 共用。形狀或調色盤改變才上傳游標 GPU 圖；移動只改座標。F12 實際畫面截圖包含游標。系統游標維持隱藏，不產生雙游標。
8. 未知尺寸或精靈格式回退原版呈現；記錄原因一次。停機時不無限等待有效畫面；診斷仍可讀原始 Frame。

## 驗收與限制

- 執行層測試：精確還原背景；透明區保持原像素；輸入副本及記憶體不變；中間階段、隱藏、邊界與異常格式；關閉選項仍原始快照。
- 前端測試：同一底圖下新鼠標座標立即生效、所有 X 餘數、選單界限、熱點、視窗外、HD 去除游標戳記；競態檢查。
- 正常 Linux GUI：標題點新遊戲、進入遊戲、移動與左右鍵，F2 三種 theme、F1、F12。錄製前後畫面，檢查游標不消失、不留舊位置影像。不得由 direct-entry 或修改狀態取代。
- 發行重新建置 Linux AppImage；其他平台編譯並保留 macOS 實機未驗的限制。沒有承諾 DOS 输入或整個遊戲加速。
- 原版精靈與背景只存在玩家的原版資料及本機研究輸出，不加入版控。規格只保存定位與契約。

## 高速設定的補取畫面

增補狀態：CONFORMED，2026-10-10。範圍限 pending 補取與完整呈現幀傳遞。證據、首次 GUI 計數勘誤及最終限制見 [033 高速設定](../re/033-cursor-presentation.md#2026-10-10-高速設定)。規格、實作及完成前唯讀審查無阻擋，報告為 `workplace/out/review-fast-cursor-implementation.md`。正常原版 A/B、受控漏讀及兩層競態測試通過。三主題正常 GUI 未再出現持續數秒消失；仍保留 17 個換圖期間短暫未命中幀的限制，不宣稱全錄影零未命中或全部已證實為正式隱藏。既有發行包未重建。

1. 範圍限於開啟 `SmoothCursor` 的呈現取樣。原版 SHA-256、40×32 精靈、背景與像素比對沿用本規格。遊戲速度、輸入、指令執行、VRAM、時鐘與存檔不變。
2. 只有消耗前端 `RequestFrame` 的初始快照取到 `CursorPending` 時，機器執行緒才記錄一次補取要求。於下一個執行期 `19FB:08A2`，原版精靈繪圖返回且 bytes 為 `83 c4 0a` 的位置取新快照。仍呼叫既有格式與逐像素驗證，不因位址符合便強制接受游標。
3. 每個前端要求最多補取一次，補取完成後無條件取消本次補取。補取仍失敗時沿用既有 500 毫秒期限；前端下一次要求可重新嘗試。沒有新 `RequestFrame` 的 100 毫秒自動回退與 `SnapshotNow` 不重新武裝補取。後續任何隱藏、未知格式、到期或非前端要求的快照取消既有補取。`SmoothCursor` 關閉時不增加快照。

   | 快照結果 | 補取狀態 |
   |---|---|
   | 前端要求且 pending，未到期 | 武裝一次 |
   | 有效游標、隱藏、未知格式或到期 | 取消 |
   | 無前端要求的快照 | 取消，不重新武裝 |
   | 補取完成，不論結果 | 取消 |

   連續 pending 沿用 `cursorWaitAt` 與同一個 500 毫秒期限，不因新要求或補取而重設。
4. 已發布的原始 Frame 與診斷保持不可變。補取與一般快照一樣，由機器執行緒製作完整 Frame，包含同一步數的 HD／UI 資訊，前端仍以整張快照配對底圖與游標。
5. 回歸須證明：由前端要求取得 pending 後，即使沒有新的前端要求，也會在繪圖返回點取得完整游標；補取失敗不反覆取樣，自動回退不重新武裝；隱藏、未知格式及到期取消補取；開關兩側相同初態與輸入跑相同步數後 CPU、記憶體、VRAM、時鐘及調色盤相同。
6. 正常 Linux GUI 從新遊戲進入設定，確認兩項高速，關閉設定後移動滑鼠與切換原版、HD、AI，錄影核對游標。不得以 state 還原取代此項。只驗本回報，停止線不擴張為額外全遊戲驗收。
7. 執行層保存最近一張完整、已接受獨立呈現的不可變 Frame，包含隱藏幀。保存的是前幀的呈現結果，已套用 `CursorBackground` 並過濾 `CursorSite`，避免原始底圖與前端游標重疊。新 pending 快照附該 Frame 指標，`Presentation()` 在原本 500 毫秒期限內回傳此完整 Frame，沒有前幀才回 nil；到期仍回原始底圖。未知格式或回退清除保存指標。保存鏈只能一層，完整 Frame 不含前幀指標，避免保留無界歷史。前端及 HD 合成器在 `Presentation()` 後再次比對返回的實際 Seq，略過已處理的完整底圖；同一 pending Frame 到期後須仍能發布 raw，不能以原始 Seq 提前阻擋。原始 `Frame.Px`、Frame.Seq 與診斷不變，呈現必須連同該 Frame 的游標、調色盤、HD／UI 資訊一起返回。受控測試須覆蓋合成器跳過一張完整幀、直接讀到後續 pending 的情形，以及正式隱藏、到期與未知格式。
