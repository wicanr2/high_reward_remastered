## 2. FBOV 區塊標頭（檔案 361856，`0x58580`）

位元組：`46 42 4F 56 | 90 B5 02 00 | D0 4C 05 00 | 90 01 00 00`

| 位移 | 型別 | 值 | 意義 | 等級與證據 |
|---:|---|---|---|---|
| +0 | u16 | `4246h`（`FB`） | 區塊族簽章 | confirmed：`3582:00B7` |
| +2 | u16 | `564Fh`（`OV`） | 區塊類型；不符時 `3582:00CA` 起用 +4 長度跳到下一個區塊 | confirmed：`3582:00C3` |
| +4 | u32 | 177552 | 標頭之後的區塊長度 | confirmed：361856 ＋ 16 ＋ 177552 ＝ 539424 ＝ 檔長；`3582:00E1` 存到 `62FF:0AD2` |
| +8 | u32 | `0x54CD0` | 段落表的檔案位移 | 值 confirmed（映像 `0x502D0` ＝ `6021:00C0`）；執行期不讀 |
| +12 | u32 | 400 | 段落表筆數 | 值 confirmed（400 乘 8 ＝ `0xC80`）；執行期不讀 |

區塊起點：`(pages − 1) × 512 ＋ last` 向上取整到 16（`3582:0080` 至 `0096`）。初始化把「區塊標頭之後」的檔案位移 361872 存到 `6021:00A4`／`00A6`。

## 3. 段落表（檔案 `0x54CD0`，400 乘 8 bytes）

| 位移 | 欄位 | 等級與證據 |
|---:|---|---|
| +0 | u16 段值（映像相對，載入時經 MZ 重定位） | confirmed：400 筆全是 MZ 重定位目標；overlay 那 139 筆就是 stub 段 |
| +2 | u16 maxoff：段的結束偏移 | overlay 筆 confirmed（139 筆都等於 `20h + 5 × 入口數`）；其餘強推論 |
| +4 | u16 旗標：bit1 ＝ overlay | bit1 confirmed（`3582:02F5`）；值分佈 0（187 筆）、1（62）、3（139）、4（12） |
| +6 | u16 minoff：段的起始偏移 | 強推論 |

overlay manager 只用 +0、+2（為 0 就跳過）、+4 的 bit1。

## 4. stub（overlay 的控制段）

139 個，映像 `0x50F60` 至 `0x52FE8`（檔案 `0x55960` 至 `0x579E8`，IDA `60F6` 至 `62F0`），每個段落對齊、互不重疊，長度 ＝ `20h + 5 × 入口數`，合計 7488 bytes。

標頭 32 bytes：

| 位移 | 檔案內的值 | 意義 | 等級 |
|---:|---|---|---|
| +00 | `CD 3F` | `int 3Fh` | confirmed（139/139） |
| +02 | 0 | 執行期：被卸載的返回偏移暫存 | 值 confirmed，語意強推論 |
| +04 | u32 相對區塊資料起點的檔案位移 | 初始化時加 361872 變絕對位移 | confirmed（`3582:0330`、`0335`） |
| +08 | u16 | code 長度 | confirmed |
| +0A | u16 | 重定位表長度（bytes），筆數 ＝ 長度/2 | confirmed |
| +0C | u16 | 入口數 | confirmed |
| +10 | 0 | 執行期載入段，0 表示未載入 | confirmed |
| +12 | 0 | 執行期全部 overlay 串列的下一個 stub | confirmed |
| +18 | 0 | 載入函式近指標，初始化設為 `0503h`（讀 code 與重定位表並套用） | confirmed；是否有 EMS 或延伸記憶體版的載入函式：未知 |
| +1A、+1B | 0 | 旗標與計數器 | 寫入點 confirmed，位元語意假說 |
| +1C | 0 | 緩衝區內已載入 overlay 的鏈 | 強推論 |
| +0E、+14、+16、+1E | 0 | 未知 | 未知 |

入口自 +20 起每筆 5 bytes：檔案內 `CD 3F lo hi 00`。u16 是函式在該 overlay code 內的偏移（608 個都落在 code 內、同段不重複、全是 IDA 函式起點）；u8 在檔案內恆為 0，載入後變成 `EA off seg`（jmp far）的最後一個 byte。載入後入口改成 `EA <off> <loadseg>`，卸載時還原。

映像內 748 個 `CD 3F` 全數有歸屬：139 個 stub 標頭、608 個入口、1 個 manager 變數（`6021:00A0`），巧合 0 個。IDA 資料庫內的入口已被 loader 改寫成 `EA`，在資料庫內搜 `CD 3F` 找不到入口。

## 5. overlay 在檔案內的排列與重定位

- 139 段（段落表 idx 252 至 390，IDA 名 ovr252 至 ovr390），順序 ＝ 段落表順序，第一段相對位移 0（檔案 361872）。每段 code（stub +08）緊接重定位表（stub +0A），再補 0 到下一段（段落對齊）。加總：code 159442 ＋ 重定位 16286 ＋ 補白 1824 ＝ 177552 ＝ FBOV +4，confirmed。補白成因（TLINK 把同段遠呼叫改成 `90 0E E8` 後空出的重定位項）強推論。
- 重定位（confirmed，`3582:045E` 至 `04A2`）：表位置 ＝ 載入段:code 長度；每筆 u16 是 code 內位移 r；`w ＝ code[r..r+1]`；值 ＝ 段落表 `[(w & 0FFF8h) / 8]` 的 +0；`code[r..r+1] ＝ 值`。8143 筆全部成立；bit0 的遠指標轉換在本檔用到 0 次；目標類別：程式段 5696、旗標 0 的段 2179、overlay 段（即 stub）268。結果與 overlay 的載入段無關（指向 overlay 的段值一律是 stub 段）。
- 與 IDA 9.4 的 DOS loader 結果逐位元組相同：139/139 段。

## 6. 呼叫方式與 `int 3Fh` 處理常式

| 方向 | 方式 | 次數 | 等級 |
|---|---|---:|---|
| 常駐碼到 overlay | `call far stub段:入口`（`9A`） | 138 | confirmed |
| 常駐碼到 overlay | 經遠指標表的間接呼叫 | 348 | confirmed |
| overlay 到其他 overlay | `call far stub段:入口` | 268 | confirmed |
| overlay 到自己 | 近呼叫；同段遠呼叫被改成 `90 0E E8` | 257 處 | confirmed |
| overlay 到常駐碼 | 直接 `call far`，段值經重定位 | 5696 ＋ 2179 | confirmed |

處理常式 `3582:0531`（執行期 `2692:0531`）：取 INT 的返回位址（stub 段:入口 ＋ 2），推入入口的 u16，把返回 IP 退 2 回到入口本身；呼叫載入常式（已載入只更新狀態，否則配置空間、經 +18 載入、把入口改寫成 `EA`）；`iret` 回到已改寫的入口進入 overlay。路徑 confirmed，實際執行面強推論（尚未在 dosgolem 內觀察到第一次 `int 3Fh`，見 `docs/re/008`）。返回位址落在被卸載的 overlay 時，manager 把堆疊上的返回改指向 stub 的 `CD 3F`，回來時重新載入（強推論）。

## 7. 緩衝區與 `0xC6D0`

| 步驟 | 內容 | 等級 |
|---|---|---|
| 單段需求 | `P ＝ ((code + 11h) >> 4) + ((重定位 + 0Fh) >> 4)` 段落 | confirmed（`3582:07EA` 至 `0801`） |
| 最小緩衝區 | `[AA] ＝ max P + 2 ＝ 1667 + 2`（最大為 ovr374） | confirmed（`3582:0350`） |
| 配置量 | `_ovrbuffer`（`dseg:0AD6`，檔案值 0）小於 `[AA]` 時配置 `2 × [AA] + 1 ＝ 3339` 段落 | 算式 confirmed，名稱強推論 |
| 可用 | 3338 段落（53408 bytes）；執行期 `55C3` 至 `62CD`，落在 `AH=4A` 擴到 `6200` 段之後的記憶體塊內 | 起點 confirmed（dosgolem 收據），終點強推論 |
| 預載 | 從串列頭依序指派載入段，放不下就停；一次 `AH=3F` 讀入，再逐段套用重定位並改寫入口 | confirmed |

含意（強推論）：初始化後這 122 段已在記憶體內、入口已是 `jmp far`，呼叫它們不會觸發 `int 3Fh`，直到被擠出緩衝區。

## 9. IDA 覆蓋與普查

`idat -A -c MAIN.EXE`（不加 loader 參數）就會建立 139 個 `stubNNN` 段與 139 個 `ovrNNN` 段，套用重定位並把 608 個入口改寫成 `jmp far`，所以 overlay 函式全被分析。覆蓋（全部 510 段）：

| 類別 | 段落 | bytes | 函式 | code head |
|---|---:|---:|---:|---:|
| 常駐 | 232 | 334478 | 708 | 56651 |
| stub | 139 | 7488 | 608 | 608 |
| ovr | 139 | 159443 | 652 | 59490 |

函式總數 1968 ＝ 708 ＋ 608 ＋ 652，code head 116749 ＝ 56651 ＋ 608 ＋ 59490。因此 `docs/re/003` 的 386 普查（22 條、14 種，全在常駐段）已涵蓋 overlay：overlay 內 386 形式為 0。

| 項目 | 常駐 | overlay |
|---|---|---|
| `int n` 指令 | 104 處 61 種 | 0 |
| `int 10h` | 15 處（`AH=01`、`AX=0003`、`1000`、`1001`、`1010`、`1800`，無 `AH=00`） | 0 |
| `int 33h`、`16h`、`2Fh`、`15h` 指令 | 0 | 0 |
| `int 81h` | 3 處（`AX=0`、`1`、`2`） | 0 |
| `int 67h` | 8 處（`281B`） | 0 |
| `in`／`out` | 未普查 | 0 |
| 呼叫 `_int86`（`1000:273D`） | 15 處 | 0 |

經 `_int86` 的軟體中斷（`int` 指令普查看不到這一類）：

- `24FF:015F`：`AH=0`、`AL=12h`，`_int86(0x10)`（`24FF:016B`、`016F`）；由 `_main`（`1975:00DA`）呼叫。位元組 confirmed；「設定視訊模式 12h」強推論，並已被 dosgolem 的收據印證（模式切換 12h）。
- `28EB` 段 14 處 `_int86(0x33)`：AX ＝ 0、3、4、5、6、7、8、0Ch、0Fh、1Dh、1Fh。overlay 透過 `28EB` 的包裝函式使用滑鼠共 30 個呼叫點（`28EB:00BD`、`0105`、`01AA`、`023A` 等）。

限制：`AH`／`AX` 只往前找 8 道指令，結果是下限；`int` 與 `_int86` 以外的進入方式沒有普查。
