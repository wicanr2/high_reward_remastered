## 2 Q1：折行路徑 `25DC:1676`（執行期 `16EC:1676`）

### 2.1 判斷表 `dseg:09D1` 與分類函式 `1000:966C`

表位置：IDA `62FF:09D1`，執行期 `540F:09D1`（線性 `54AC1`），`MAIN.EXE` 檔案位移 `0x583C1` 起 256 bytes，SHA-256 `bfde2dddad6a8997707079bd1131e597eeb93dc4f9d95c7904ac7404ecce20d8`。IDA 資料庫位元組與檔案位元組相同（`corpus-summary.txt` 第 8 行）。

| 值 | 範圍 | 位元語意 |
|---|---|---|
| `00` | `00` 至 `3F`、`7F`、`FD` 至 `FF` | 無 |
| `08` | `40` 至 `7E`、`80`、`A0` | bit 3（0x08）：可當 trail |
| `0A` | `A1` 至 `A5` | bit 1（0x02）＋0x08 |
| `09` | `A6` 至 `DF` | bit 0（0x01）＋0x08 |
| `0C` | `81` 至 `9F`、`E0` 至 `FC` | bit 2（0x04）＋0x08：lead |

bit 0 與 bit 1 的名稱（半形片假名本體、標點）是依 Shift-JIS 慣例的推測（強推論）；它們在 `966C` 的作用是 `test …, 3`，只決定「單位元組合法」。

`1000:966C(c, mode)` 的位元組與邏輯（confirmed）：

| 位址 | bytes | 作用 |
|---|---|---|
| `1000:9677` | `3d 01 00 75 18` | `mode == 1` 走 trail 測試，否則跳 `9694` |
| `1000:9687` | `26 f6 87 d1 09 08` | `test [c+9D1h], 8`：有 → 回 2，無 → 回 -1 |
| `1000:9694` | `0b c0 74 0a`、`3d 02 00 74 05`、`3d ff ff 75 42` | `mode` ＝ 0、2、-1 才進 lead 測試，其餘回 -1 |
| `1000:96AD` | `26 f6 87 d1 09 04` | `test [c+9D1h], 4`：有 → 回 1（lead） |
| `1000:96C5` | `26 f6 87 0f 04 de` | `test [c+40Fh], 0DEh`（Borland `__ctype+1`）：非零 → 回 0 |
| `1000:96D8` | `26 f6 87 d1 09 03` | `test [c+9D1h], 3`：零 → 回 -1（`0xFFFF`），否則回 0 |

`1676` 只呼叫 `mode = 0`（`25DC:1689` `6a 00`，`1692` `9a 6c 96 00 10`）。對 `MAIN.EXE` 文字常見的位元組，回傳值是：

| 回傳 | 位元組 | `1676` 走的路徑 |
|---|---|---|
| 0 | `20` 至 `7E`、`A1` 至 `DF` | 單位元組 |
| 1 | `81` 至 `9F`、`E0` 至 `FC` | 成對 |
| -1 | `00` 至 `1F`（`00`、`0A` 先被迴圈頂端擋掉）、`7F`、`80`、`A0`、`FD` 至 `FF` | 成對（`or ax, ax; jz` 只在回傳 0 時跳走，-1 也落入成對路徑） |

結論：lead 在 `1676` 眼中的範圍是 `E0` 至 `FC`（與 `81` 至 `9F`）；Big5 的 `A1` 至 `DF` 是單位元組。020 第 3.1 節與規格 008 第 42、104 行寫的「`A4` 至 `DF`」不對，`A1` 至 `A3` 符號區也在內。審查 A 正確。

### 2.3 主張的驗證

審查 A 的 B4 主張：「成對路徑畫完 lead 後會無條件畫下一個位元組，不檢查 `0x0A`；觸發條件是行尾字 lead 在 `A1` 至 `DF`、trail 在 `E0` 至 `FC`，會吞掉換行讓兩行併成一行」。

推理（confirmed）：行尾字 `(L, T)`，`L` 在 `A1` 至 `DF` → 單位元組路徑；下一輪迴圈頂端 `T` 在 `E0` 至 `FC` → 回傳 1，走成對路徑；步驟 2 畫 `T`，步驟 3 只查寬度與 NUL，步驟 4 把後面的 `0x0A` 當半形字畫出（`287C:0002`：`al = c - 14`，字模索引超出 85 格表，畫出雜訊字模），行不斷，後一行接在同一列。

指令級模擬（`ida_text2_corpus.py`，逐指令對應上表）與簡單規則（行尾字 lead `A1` 至 `DF`、trail `E0` 至 `FC`、後接 `0x0A`）找出的位置集合完全相同（38 行，已用 shell 比對）。

**動態對照實驗**（confirmed）。做法：複製原版目錄，只改 `ESPMES.MRG` 檔案位移 `0x3D7A` 起的 22 bytes（`ESPMES#121.0`，冷啟動新遊戲第一句對白，外層 id 211、子 id 0，走對話框 `01A3`），其他位元組不動。冷啟動 `-clicks "35000000:312:211"`，跑 49.6M 步，記 `16EC:1676` 的呼叫。

| 變體 | 內容（位元組） | `1676` 呼叫（x, y, 最大寬, …, 字串偏移） | 畫面 |
|---|---|---|---|
| ctl（原檔） | 原版 | 2 次：y ＝ 110（偏移 1059）、y ＝ 126（偏移 1068） | 兩行 |
| T0（對照） | `A440 A441 A47E 0A A442 … A448 00` | 2 次：y ＝ 110（偏移 1059）、y ＝ 126（偏移 1066，第一行消耗 7 bytes） | 兩行（`shot-t0.png`） |

補充實驗 T3a／T3b（confirmed）：單位元組類 lead（`A4`）剛好落在第 31 位元組（最大寬 248）。`ESPMES#121.1`（外層 id 211、子 id 1，第二句對白，檔案位移 `0x3D90`）換成 29 個 `A4xx` 字，第 16 字 `A44F`（T3a）或 `A4E0`（T3b）。`1676` 兩次呼叫的字串偏移為 1059、1090（第一行消耗 31 bytes，與模擬一致）。畫面：第 16 字完整畫在第一行行尾（`x` 偏移 240 至 255，剛好在 256 寬窗口內），第二行以 8 像素空白開頭，其後字元照常（`shot-t3a.png`、`shot-t3b.png`）。結論：lead 在 `A1` 至 `DF` 的字在寬度邊界不會畫壞，只讓下一行縮排 8 像素。020 第 3.1 節「強推論」的「拆開後畫在上一行尾端」成立。

## 7 Q6：`CFONT.15` handle 在 `_lseek` 與 `_read` 之間被換掉是否安全（靜態推論）
