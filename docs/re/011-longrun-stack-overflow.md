# 011 長跑、停機分類與堆疊溢位

日期：2026-10-03
範圍：`MAIN.EXE` 在 dosgolem 內的長時間隨機輸入執行（M4），停機點的分類，以及找到的第一個可重現當機：堆疊溢位（M5 的起點）。不含 `OP.EXE`、`END.EXE`、`PSH.EXE`。
輸入：`MAIN.EXE`（SHA-256 `08ed144e8f8d6e97d19f0759bce2420665998143f2f0f056ab7adc718e550e3e`）、`GAMEFILE.000` 至 `.004`（5 個存檔槽，內容互不相同，`docs/re/001`）。
工具：`tools/dosgolem.sh soak`（`workplace/dosgolem` 分支 `hr` 的 `apps/hr/cmd/hrsoak`，commit `14c13a9`）、`probe`；IDA Pro 9.4（`tools/ida.sh`，`tools/ida_dump_ranges.py`）。
推論等級：confirmed（可由指令重跑並比對）、強推論、假說、未知。位址寫法：執行期 `段:偏移`；IDA 選擇子 ＝ 執行期段 ＋ `0x0EF0`（常駐映像，`docs/re/007`）。

## 1. 方法

長跑驅動 `hrsoak` 讀入存檔槽（腳本點擊標題選單的讀取遊戲與槽位），之後以固定種子的偽隨機輸入跑：每 1.5M 至 4.5M 道指令一個事件，70% 左鍵、10% 右鍵、12% 按鍵（Enter、Esc、空白、方向鍵；見第 1 節末的更正，這些按鍵實際沒有被遊戲讀到）、8% 只移動。滑鼠按住到遊戲輪詢 3 次才放開。每回報期（2.5 億至 10 億道指令）寫一行資源計數到 `report.tsv`。

| 項目 | 做法 |
|---|---|
| 模擬時間 | 計時器中斷次數 × 65536 ÷ 1193182。PIT 通道 0 的 65536 分頻（18.2 Hz）是 dosgolem 的開機預設，遊戲沒有寫 PIT 埠（`docs/re/010` 第 1 節）。dosgolem 約每 636,000 道指令送一次中斷，所以約 11.6M 道指令是 1 模擬秒。80 億道指令約 691 模擬秒 |
| 診斷紀錄 | dosgolem 為觀測把檔案、滑鼠、記憶體服務等紀錄放在無上限切片。每 200 萬道指令清空一次，否則 10 億步左右被容器記憶體上限殺掉 |
| overlay 覆蓋 | 對 `MAIN.EXE` 的讀取起點去重（FBOV overlay 管理員自己讀檔，`docs/re/007`）。這是下限指標，不是 139 個 overlay 的精確計數 |
| 停機條件 | CPU 解不出 opcode、`CS:IP` 進入視訊記憶體位址範圍、程式結束、`HLT`、除以零、堆疊溢位（`SS` 為堆疊段且 `SP` 大於頂端）、一個回報期內滑鼠沒被輪詢（凍結） |
| 現場 | 停機時存狀態檔與最近 16 個輸入；可選的指令軌跡環（最近 N 道指令的暫存器） |


更正（審查發現）：`MAIN.EXE` 只用 `int 21h` 的 `AH=08`、`0B`、`0700` 讀鍵盤（`docs/re/004`），dosgolem 的這幾個服務只讀 `d.Stdin`；早期長跑用的 `PushKey` 寫的是 BIOS 鍵盤緩衝，沒有人讀，所以第 3 至 6 節各組的 12% 按鍵事件都是空操作（只有滑鼠輸入有效）。`hrsoak` 現在有 `-key-path`：`stdin`（預設，擴充鍵送 `00` 加掃描碼）與 `bda`（舊行為，重現舊收據用）。第 5 節與 5.1 節的 A/B 全部用 `bda` 重現舊結果；5.1 節另有兩對用 `stdin`。
## 2. 停機分類

| 類別 | 判準 | 本次觀察 |
|---|---|---|
| 玩家結束遊戲 | 結束碼 1。`HR.BAT`：`MAIN` 之後 `if errorlevel 1 goto quitprog`。停機當下的畫面是遊戲自己的「請關閉電源再見」 | 第一次出現在存檔槽 4、種子 14，第 765,558,229 步，重現兩次同步數。confirmed |
| 進入片尾 | 結束碼 0（`HR.BAT` 接著執行 `END`） | 未出現 |
| 堆疊溢位 | `SS:SP` 超過堆疊頂端（SP 減過 0 繞回 `FFxx`） | 第 4 節 |
| 其他結束碼、CPU 錯誤、跑出記憶體、凍結 | 其他 | 除第 4 節外未出現 |

結束碼 0 與 1 是正常結束，驅動退回最近的復原點、換亂數序列繼續跑，並在 `report.tsv` 記一行。復原點保留多份時退回最舊的一份：只留最近一份時曾出現「復原點恰在結束流程之後」而無限重複結束（種子 24 的長跑重複 33,377 次，被 40 分鐘上限終止）。

## 4. 堆疊溢位

### 4.1 停機點（confirmed）

存檔槽 2、種子 22（命令見第 7 節）在第 3,093,737,047 步停機：`CS:IP ＝ A39A:006A`（線性 `A3A0A`，視訊記憶體範圍）。此時 `SS:SP ＝ 54C0:7406`、`DS ＝ 05DC`，暫存器都已是垃圾。同種子重跑兩次，步數與暫存器逐位元相同。現場前的位元組是 `FF FD DD DD 55 55 55 55 ...`，是圖形資料而非程式碼。

### 4.2 指令軌跡（confirmed，除另標）

停機前 20 萬道指令的軌跡環（暫存器含 BP、SI、DI）：

1. 前 118,342 道指令在 `24BD:0D3E` 的函式（IDA `33AD:0D3E`，從檔案 handle 讀並解 LZSS 到記憶體，`docs/re/009` 第 3 節；`24BD:0CFA` 屬於 `0CE8` 起的輔助函式）與 `1C20:00A8` 之間迴圈。這段期間 `BP ＝ FFF2`、`SP` 在 `FFBA` 至 `FFF4` 之間：函式的框架在堆疊段頂端，而不是在 `0x1010` 以下。
2. 該函式結束時 `pop bp` 把 `BP` 還成 `0x0028`，返回 `160F:08C4`（IDA `24FF:08C4`；同一函式含程式內字串 `Can't open file in hloadGraph`，以字串稱呼，不是 IDA 名稱）。呼叫端 `BP ＝ 0x0028`：它的框架在 `54C0:0028`，只比堆疊底部高 40 bytes，也就是堆疊已用掉約 99%。該函式為呼叫推入參數（`160F:0888` 起，累計 `0x22` bytes，由 `add sp, 22h` 清理）時，`SP` 減過 0，繞到 `FFxx`。上一段的 24BD 函式與 1C20 函式就跑在繞回後的 `FFxx`。
3. `160F:08CA` 的 `add sp, 22h` 讓 `SP` 由 `FFF6` 加回 `0x0018`，函式正常返回（`pop ds`、`pop di`、`pop si`、`leave`、`retf` 取到的都是正確值）。單是繞回不造成當機，因為繞回區域在那時還沒有被別的資料覆蓋。
4. 之後 `18D5:024D` 在 `SP ＝ 0x0004` 呼叫 `1F69:000E`（IDA `2E59:000E`，把 VRAM 矩形存進記憶體，`docs/re/009`）。該函式開頭以 `enter` 與連續 6 次 `push`（`1F69:0012` 至 `0017`），`SP` 由 `0x0000` 繞到 `FFF2`，暫存器存在 `54C0:FFF2` 至 `FFFE`。函式把矩形寫進 `ES:DI`，`ES ＝ 6497`（線性 `0x64970`）；`54C0:FFF2` 的線性位址是 `0x64BF2`，在寫入範圍內（強推論：寫入長度未逐位元核對）。
5. 結尾的 `pop` 讀到 `0x5555`（像素樣式，軌跡 `1F69:009F` 的 `ES ＝ 5555`、`1F69:00A0` 的 `DS ＝ 5555`），`1F69:00A6` 的 `leave` 以 `BP ＝ 0x8555` 設 `SP ＝ 0x8557`，`1F69:00A7` 的 `retf` 取到垃圾位址，跳進 `0005:3D0D`，之後執行資料，最後 `A39A:006A`。

結論：堆疊在 `160F` 的函式裡第一次繞回；繞回後的堆疊區域與一個圖形緩衝區重疊，函式 `1F69:000E` 在這個區域存暫存器又寫入同一塊記憶體，返回時取到像素資料。

### 4.3 堆疊的大小（confirmed）

| 項目 | 內容 |
|---|---|
| `MAIN.EXE` 標頭 | `e_ss ＝ 53B0`、`e_sp ＝ 0080`；載入段 `0110`，所以 `SS ＝ 54C0` |
| 啟動碼 | IDA `1000:0062` 從 DGROUP `540F:040C` 讀 `_stklen`，補到最少 `0x200`，轉成段落數，用 `AH=4Ah` 調整程式區塊到 `SS` 之後該長度，再設 `SP ＝ _stklen + 0x10`（`1000:009E` 至 `00A1`） |
| `_stklen` 值 | 原版檔案位移 `0x57DFC`，位元組 `00 10`，`0x1000`（4096）。所以 `SP` 起點 `0x1010` |
| 閒置時的 `SP` | 地圖閒置輪詢 `0EDE` 一帶（深度約 300 bytes）；選單中 `0B6C`、`0B36`、`0AD0`、`073C`（深度 `0x1010 −` 該值，約 0x4A4 至 0x8D4） |

### 4.4 深度的來源（confirmed）

`-sp-log` 在每個輸入事件記錄閒置輪詢點的 `SP` 與 `BP` 鏈。種子 22 的 899 個事件（`sp.tsv` 900 列含標題列；`0EDE` 佔 539 個）：

- 閒置基準 `0EDE` 全程不變，沒有逐次洩漏。
- 進入選單與子選單時，呼叫鏈一層層加深：`main(0A85:032B) → 0E3C:00F7 → 5B76:12BB → 5D2C:065E → 5D2C:0E3A → 5D2C:00F0 → 16EC:0E9D → 1043:03B0 → 16EC:1D9E`（最深一串的事件 `3085823343` 後，`SP ＝ 073C`）。`5Bxx` 與 `5Dxx` 是 overlay 緩衝區內的段，同一個 overlay 在不同時刻載入的段值不同。
- 此後在最深的選單內的操作觸發載入圖形的函式（上一小節），從閒置 `SP ＝ 073C` 再往下用了超過 `0x073C`（1852）bytes，`SP` 減過 0。

遊戲以巢狀呼叫實作選單，返回前不展開。隨機輸入走得比玩家深：右鍵取消（10%）少於進入新選單的左鍵。玩家是否會走到相同深度，未知。

## 5. 同狀態比對（confirmed）

同一組輸入（種子 22、存檔槽 2、`-recover-depth 1`），只改 `_stklen`：

| `_stklen` | 結果 | 本期最低 `SP` 與深度 |
|---|---|---|
| `0x1000`（原版） | 第 3,093,473,639 步 `SS:SP ＝ 54C0:FF52`，偵測到溢位。不加偵測則第 3,093,737,047 步跳進 `A39A:006A`（相差 263,408 步） | 偵測前最低 `0824` 之後繼續下降 |
| `0x4000` | 跑滿 45 億步，無停機。畫面雜湊 `b43bc072e2b3` | `2B7E`；深度 `0x4010 − 0x2B7E ＝ 0x1492 ＝ 5266` bytes |

### 5.1 行為對照與偵測器對照（confirmed）

`_stklen` 改變程式區塊的大小，所以記憶體內容不能逐位元比對：overlay 緩衝區與遠堆積整體上移 `0x700` 段落（原版 `5D2C` 在修補後是 `642C`），指向它們的指標跟著變。對照改用遊戲可觀察與可序列化的內容：

| 對照項目 | 方法 | 結果 |
|---|---|---|
| 事件序列 | `-sp-log` 記錄每個輸入事件的步數、輸入、閒置輪詢點的呼叫鏈（overlay 段位址只留偏移）與堆疊深度（頂端 `−` SP） | 存檔槽 2、種子 22：原版（`-stklen 0 -no-overflow-stop`）與修補（`-stklen 32768`）各 900 列逐列相同。存檔槽 0、種子 40 與存檔槽 3、種子 43（`-key-path stdin`，25 億步）各 713 列逐列相同 |
| 畫面 | 每 2.5 億步的畫面索引色雜湊序列 | 種子 22：停機前的 11 筆逐筆相同 |
| 存檔內容 | 讀取存檔槽 0，開系統選單，存入存檔槽 0（腳本同一組步數），比對暫存層的 `GAMEFILE.000` 與 `FNAME.DAT` | 兩邊逐位元相同（`GAMEFILE.000` MD5 `153af2092c8849984cc17a412f5cf46a`，`FNAME.DAT` MD5 `8a5faca67446164b98e41e3da16f4599`） |
| 偵測器正對照 | `-stklen 1024`（頂端 `0x0410`），種子 22、存檔槽 2 | 第 276,898,405 步報堆疊溢位（`SS:SP ＝ 54C0:FFF8`，頂端 `0410`） |
| 原版後果重現 | `-stklen 0 -no-overflow-stop`（關掉溢位停機，其餘同第 5 節） | 第 3,093,737,047 步跳進 `A39A:006A`，與第 4.1 節逐位元相同 |

未對照：調色盤雜湊（`report.tsv` 沒有這一欄）；溢位之後兩邊本來就不同。所有對照在 dosgolem 內，沒有 DOSBox-X。

## 7. 重跑

```text
tools/dosgolem.sh build
# 對照組：原版堆疊，同種子
tools/dosgolem.sh soak -steps 3100000000 -report-every 250000000 -checkpoint-every 0 -out /out/ab-0 \
  -input random -seed 22 -start-click 35000000:312:228 -script /out/load-slot2.txt -random-from 200000000 \
  -stklen 0 -recover-depth 1
# 修補組
... -stklen 32768 ...
```

`load-slot2.txt` 內容是一行：`90000000 click 312 341`（存檔槽 2；槽 k 的 y 為 `307 + 17k`）。標題選單的讀取遊戲點 `(312, 228)`。

## 8. 限制

- dosgolem 是決定性的：計時器中斷固定每 `IRQ0Every` 道指令一次。原版若有計時器中斷與主迴圈的競態，這個環境永遠不進那個窗口。`-tick` 可以擾動，本份只用預設值。「沒重現」不等於「沒有」。
- 隨機輸入不是玩家：一組 80 億步（約 11 模擬分鐘）只讀到 17 至 20 個 overlay 讀取起點。戰鬥、商店、事件各在不同 overlay，覆蓋不足。系統性探索見 `docs/re/012`（進行中）。
- 堆疊段上方 `54C0:FFxx`（線性 `640BE` 附近）在真實 DOS 是什麼，沒量測。能否直接把 dosgolem 的結果推到真實機器，需要位元組層級的一致，未做。
- 使用者描述的當機是「進入遊戲後長時間跑才會知道」。本份找到的堆疊溢位與這個描述相容，但沒有症狀（凍結、花屏、回到 DOS、重開）可對照，不能確認是同一個當機。
- 音樂路徑關閉（`docs/re/010`）：驅動缺席、`SOUND` 未設，音樂與音效都不執行。若原版當機與音效路徑有關，這次量不到。
